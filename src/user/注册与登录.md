# 安全电子商务系统 — 用户认证模块

> 数据地基与用户模块（Database Foundation & User Module）
> 技术栈：原生 Python 3.8+ ｜ 零第三方依赖 ｜ SQLite

---

## 一、项目概述

本模块是「安全电子商务系统」的基础数据层与用户身份层，负责在数据库层面把用户账号体系立起来，并提供注册、登录、登出、查询当前用户四个核心能力。

设计上遵循三条硬性原则：

| 原则 | 含义 | 落地手段 |
| --- | --- | --- |
| **口令不落明文** | 数据库任何字段都不出现原始口令 | PBKDF2 慢哈希 + 随机盐，算法/迭代/盐/派生值四列分离 |
| **错误不泄露信息** | 攻击者无法通过响应差异枚举账号 | 登录失败统一 `401 AUTH_INVALID_CREDENTIALS` |
| **凭据可吊销** | Token 泄露后能被立即废止 | 明文不入库，仅存 SHA-256 摘要；登出写入黑名单 |

技术选型说明：全部使用 Python 标准库（`sqlite3`、`hashlib`、`hmac`、`secrets`、`http.server`、`json`、`uuid`），不引入任何第三方包，保证在离线环境、内网环境、教学环境中都能一条命令跑起来。

## 二、目录结构

```text
.
├── src/
│   ├── __init__.py
│   ├── crypto/
│   │   ├── __init__.py
│   │   └── 加盐哈希.py          # PBKDF2 慢哈希 / 恒定时间比对
│   └── user/
│       ├── __init__.py
│       ├── db.py                # 数据库初始化与连接管理
│       ├── auth_token.py        # Token 生成、摘要与黑名单
│       ├── password.py          # 口令封装（四列结构）
│       ├── auth_service.py      # 核心业务逻辑与鉴权
│       └── server.py            # HTTP 路由与全局异常拦截
└── mydocs/
    └── client_demo.py           # 全流程验收脚本
```

各文件职责：

- **`src/crypto/加盐哈希.py`**：只做纯粹的密码学运算，不碰数据库、不碰业务。对外暴露「派生」与「校验」两个函数，校验内部使用 `hmac.compare_digest` 做恒定时间比对，避免时序侧信道。
- **`src/user/db.py`**：建库建表、建立索引，提供连接工厂。可直接以模块方式运行完成初始化。
- **`src/user/auth_token.py`**：生成高熵随机 Token，计算其 SHA-256 摘要入库；负责黑名单的写入与查询。
- **`src/user/password.py`**：把算法名、迭代次数、盐、派生值打包成一个值对象，负责序列化与反序列化，杜绝"顺手把明文存进去"的可能。
- **`src/user/auth_service.py`**：唯一的业务入口，注册、登录、登出、取当前用户都在这里，路由层不得绕过它直接操作数据库。
- **`src/user/server.py`**：轻量 HTTP 层，负责解析请求、路由分发、统一异常拦截与响应封装。

## 三、核心安全控制（验收口径）

### 3.1 口令字段拆四列

`users` 表中与口令相关的字段严格分离为四列，**不存在 `password` 或 `pwd` 这样的明文字段**：

| 列名 | 类型 | 说明 |
| --- | --- | --- |
| `password_algo` | TEXT | 算法标识，如 `pbkdf2_sha256`，为未来平滑升级预留 |
| `password_iterations` | INTEGER | 迭代次数，如 `200000`，随算力增长可调 |
| `password_salt` | TEXT | 每用户独立随机盐（16 字节，hex 编码） |
| `password_hash` | TEXT | 派生值（32 字节，hex 编码） |

拆列的收益：算法可迁移（老用户登录时按新参数重算并原地升级）、迭代次数可调、盐与派生值互不耦合，任何一个字段被单独读取都无法还原口令。

### 3.2 PBKDF2 慢哈希与恒定时间比对

- 算法：`hashlib.pbkdf2_hmac("sha256", password, salt, iterations)`
- 盐：`secrets.token_bytes(16)`，**每个用户独立生成**，注册与改密时重新生成
- 迭代：默认 `200000`，写入数据库随行存储，校验时以库中值为准
- 比对：`hmac.compare_digest(计算值, 存储值)`，**不使用 `==`**

### 3.3 防信息泄露

| 场景 | 响应 | 说明 |
| --- | --- | --- |
| 账号不存在 | `401 AUTH_INVALID_CREDENTIALS` | 与口令错误返回完全一致，不暴露账号是否存在 |
| 口令错误 | `401 AUTH_INVALID_CREDENTIALS` | 同上 |
| 未携带 / 无效 Token | `401 AUTH_UNAUTHENTICATED` | 与凭据错误区分，但同样不透露内部细节 |
| 服务端未预期异常 | `500 INTERNAL_ERROR` + `traceId` | 不返回堆栈，仅返回可追溯的 traceId |

统一响应体形如：

```json
{
  "error": {
    "code": "AUTH_INVALID_CREDENTIALS",
    "message": "账号或密码不正确",
    "traceId": "3f6c1e2a-9b7d-4c1e-8a55-0d2f7b1c9e10"
  }
}
```

### 3.4 Token 安全

- **明文不入库**：Token 只在签发瞬间返回给客户端，数据库仅保存其 SHA-256 摘要。即使数据库被拖走，攻击者也无法反推出可用 Token。
- **摘要比对**：每次鉴权时对请求携带的 Token 计算摘要，再与库中摘要比对。
- **登出即吊销**：登出时把该 Token 的摘要写入黑名单表，后续携带同一 Token 的请求一律 `401 AUTH_UNAUTHENTICATED`。
- **有效期**：Token 记录签发时间与过期时间，过期后无论是否在黑名单中均拒绝。

### 3.5 可观测性

每个请求生成一个 `traceId`（UUID4），贯穿日志与错误响应。排查线上问题时，凭客户端截图里的 traceId 即可在日志中定位到唯一一次请求。

## 四、数据库设计

### users

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK AUTOINCREMENT | 主键 |
| `username` | TEXT | UNIQUE NOT NULL | 登录名 |
| `email` | TEXT | UNIQUE | 邮箱，可空 |
| `password_algo` | TEXT | NOT NULL | 算法标识 |
| `password_iterations` | INTEGER | NOT NULL | 迭代次数 |
| `password_salt` | TEXT | NOT NULL | 盐（hex） |
| `password_hash` | TEXT | NOT NULL | 派生值（hex） |
| `created_at` | TEXT | NOT NULL | 创建时间（ISO8601） |

### auth_tokens

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK AUTOINCREMENT | 主键 |
| `user_id` | INTEGER | NOT NULL | 关联 users.id |
| `token_digest` | TEXT | UNIQUE NOT NULL | Token 的 SHA-256 摘要 |
| `issued_at` | TEXT | NOT NULL | 签发时间 |
| `expires_at` | TEXT | NOT NULL | 过期时间 |
| `revoked` | INTEGER | NOT NULL DEFAULT 0 | 是否已吊销 |

### token_blacklist

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK AUTOINCREMENT | 主键 |
| `token_digest` | TEXT | UNIQUE NOT NULL | 被吊销 Token 的摘要 |
| `revoked_at` | TEXT | NOT NULL | 吊销时间 |

## 五、API 契约

统一约定：请求与响应均为 `application/json; charset=utf-8`；需要鉴权的接口在请求头携带 `Authorization: Bearer <token>`。

### 5.1 注册

```http
POST /api/users/register
Content-Type: application/json

{
  "username": "alice",
  "password": "S3cure!Passw0rd",
  "email": "alice@example.com"
}
```

成功响应 `201 Created`：

```json
{
  "id": 1,
  "username": "alice",
  "createdAt": "2026-11-03T09:20:11+08:00"
}
```

失败：
- `400 VALIDATION_ERROR` — 字段缺失、口令强度不足、用户名格式非法
- `409 USER_ALREADY_EXISTS` — 用户名或邮箱已被占用

### 5.2 登录

```http
POST /api/auth/login
Content-Type: application/json

{
  "username": "alice",
  "password": "S3cure!Passw0rd"
}
```

成功响应 `200 OK`：

```json
{
  "token": "vT9x...（仅此一次返回明文）",
  "expiresAt": "2026-11-04T09:20:11+08:00"
}
```

失败：`401 AUTH_INVALID_CREDENTIALS`（账号不存在与口令错误返回相同结果）

### 5.3 登出

```http
POST /api/auth/logout
Authorization: Bearer <token>
```

成功响应 `200 OK`：

```json
{ "success": true }
```

副作用：该 Token 摘要写入黑名单，立即失效。

### 5.4 查询当前用户

```http
GET /api/users/me
Authorization: Bearer <token>
```

成功响应 `200 OK`：

```json
{
  "id": 1,
  "username": "alice",
  "email": "alice@example.com",
  "createdAt": "2026-11-03T09:20:11+08:00"
}
```

失败：`401 AUTH_UNAUTHENTICATED`（未携带、格式错误、已过期、已被吊销、被篡改）

> 注意：`/api/users/me` 的响应中**不包含任何口令相关字段**。

## 六、运行与启动指南

### 6.1 环境准备

要求 Python 3.8 及以上，无需安装任何第三方包。

确保 `src/`、`src/crypto/`、`src/user/` 各级目录下都存在空的 `__init__.py`，否则包导入会失败：

```bash
# Windows
type nul > src\__init__.py
type nul > src\crypto\__init__.py
type nul > src\user\__init__.py

# macOS / Linux
touch src/__init__.py src/crypto/__init__.py src/user/__init__.py
```

### 6.2 初始化数据库

在项目根目录执行：

```bash
python -m src.user.db
```

该命令会创建 SQLite 数据库文件、建表、建索引，并在控制台输出初始化结果。

### 6.3 启动服务端

**必须使用模块方式启动**：

```bash
python -m src.user.server
```

不要使用 `python src/user/server.py`。直接以脚本路径运行会让 `sys.path` 指向 `src/user/`，包内相对导入（`from ..crypto.加盐哈希 import ...`）会抛出 `ImportError: attempted relative import with no known parent package`。

服务默认监听 `127.0.0.1:8000`，启动成功后会打印监听地址。

### 6.4 运行测试

另开一个终端，保持服务端运行，执行：

```bash
python mydocs/client_demo.py
```

脚本会依次走完：注册 → 登录 → 携带 Token 访问 `/api/users/me` → 登出 → 用同一 Token 再次访问（预期被拒），逐条打印断言结果，全部通过即视为验收通过。

## 七、验收自查与避坑指南

### 7.1 自查：确认数据库无明文

一行命令直连 SQLite，打印表结构与全部用户数据，目视确认没有任何字段等于你注册时输入的明文口令：

```bash
python -c "import sqlite3,glob;db=glob.glob('**/*.db',recursive=True)[0];c=sqlite3.connect(db);print(*[r for r in c.execute('select name,sql from sqlite_master')],sep='\n');print(*c.execute('select * from users').fetchall(),sep='\n')"
```

逐项核对：

- [ ] `users` 表存在 `password_algo` / `password_iterations` / `password_salt` / `password_hash` 四列
- [ ] 不存在名为 `password` 的列
- [ ] `password_salt` 与 `password_hash` 均为长 hex 串，且不同用户之间盐不相同
- [ ] `auth_tokens.token_digest` 为 64 位 hex（SHA-256），不是登录响应里的那串 Token

### 7.2 篡改测试

把登录拿到的 Token 任意改动一个字节（改一位字符即可），再请求：

```bash
curl -i http://127.0.0.1:8000/api/users/me -H "Authorization: Bearer <被篡改的Token>"
```

预期返回 `401` 且错误码为 `AUTH_UNAUTHENTICATED`。若返回 `200`，说明摘要比对环节失效。

### 7.3 避坑点

1. **工具文件绝不能命名为 `token.py`**
   Python 标准库中存在 `token` 模块。一旦在 `src/` 或更外层放置 `token.py`，导入 `tokenize` / `inspect` 等标准库时会被你的文件劫持，导致解释器启动阶段就崩溃，且报错信息极具误导性（形如 `AttributeError: module 'token' has no attribute ...`）。本项目统一命名为 `auth_token.py`。

2. **HTTP Header 中不能包含中文 Token**
   HTTP 头部按 latin-1 编码传输，中文 Token 会触发 `UnicodeEncodeError` 或产生乱码。Token 由 `secrets.token_urlsafe()` 生成，天然是 ASCII 安全字符集；如果自行拼接 Token，务必保证只含 `[A-Za-z0-9_-]`。

3. **必须用 `-m` 方式启动服务**
   原因见 6.3 节。以 `-m` 运行时 Python 会把当前目录加入 `sys.path`，包内相对导入才成立。

4. **SQLite 连接不要跨线程复用**
   `sqlite3` 的连接默认绑定创建它的线程。`http.server` 若启用多线程处理，应为每个请求单独取连接，或使用 `check_same_thread=False` 并自行加锁。

5. **`compare_digest` 只接受同类型、等长的 bytes**
   比对前先将 hex 字符串统一用 `bytes.fromhex()` 或 `.encode("utf-8")` 转成 `bytes`，不要混用 `str` 与 `bytes`，否则会抛 `TypeError` 而不是返回 `False`。

## 八、常见问题

**Q：忘记跑数据库初始化，启动服务报 `no such table: users`？**
A：执行 `python -m src.user.db` 后重启服务。

**Q：`client_demo.py` 报连接被拒绝？**
A：先确认服务端窗口仍在运行，且监听地址与脚本中的 `BASE_URL` 一致。

**Q：想调整口令强度或迭代次数？**
A：迭代次数在 `src/user/password.py` 的默认参数中调整。已注册用户的旧参数保留在库中，可在登录成功时按新参数重算并更新，实现平滑升级。

**Q：Token 有效期是多久？**
A：默认 24 小时，见 `src/user/auth_token.py`。生产环境建议缩短至数小时，并配合刷新机制。
