## 1. 这份交付管什么、不管什么

**管**：四个入口（注册、登录、退出、本人信息）在**进入业务逻辑之前**的校验——类型、
长度、格式、禁用字段、请求体形状；校验失败时对外说什么；日志里不出现什么。

**不管**（由组内其他成员负责，本层只提供被调用的接口）：

| 不在本层 | 归属 | 本层如何配合 |
| :--- | :--- | :--- |
| 建库脚本 `db/schema.sql`、四列口令字段 | 数据地基 | `password_port.split_stored()` 把存储串拆成四列 |
| 注册落库、登录认证、令牌签发与撤销 | 用户模块业务 | 校验通过后返回 `RegisterInput` / `LoginInput` |
| 鉴权中间件、限流、会话撤销 | 后端平台 | 本层不做计数与锁定，只做单次请求校验 |
| 前端表单提示 | 前端 | 本层只给错误码与字段级原因，文案由契约固定 |

一句话：**本层回答"这个请求能不能往下走"，不回答"这个人是谁、能不能做这件事"。**

## 3. 每个入口校验什么

### 3.1 注册 `POST /api/users/register` → `validate_register()`

| 项 | 规则 | 失败原因 |
| :--- | :--- | :--- |
| Content-Type | 媒体类型必须是 `application/json`（允许带 charset） | 400，不带 details |
| 请求体体积 | ≤ 4 KB（按原始字节量，反序列化前判） | `413 PAYLOAD_TOO_LARGE` |
| JSON 形状 | 必须是 UTF-8 编码的 JSON **对象**；拒绝空体、数组、语法错、重复键 | 400，不带 details |
| `username` | 必填，字符串，去首尾空白后 4—32 字符，匹配 `^[A-Za-z0-9_]{4,32}$` | `REQUIRED` / `TYPE_MISMATCH` / `TOO_SHORT` / `TOO_LONG` / `FORMAT_INVALID` |
| `phone` | 必填，字符串，去掉空格与连字符后匹配 `^1[3-9]\d{9}$` | `FORMAT_INVALID` 等 |
| `password` | 必填，字符串，8—64 字符，UTF-8 ≤ 256 字节，不得全为同一字符，不得等于 `username` 或 `phone` | `TOO_SHORT` / `TOO_LONG` / `FORMAT_INVALID` |
| 禁用字段 | `userId`、`role`、`status`、`iterations`、`salt`、`passwordHash`、`passwordDerived` | `NOT_ALLOWED`（点名，字段名是契约常量） |
| 未知字段 | 除上述三个字段外一律拒绝（`additionalProperties: false`） | 400，**不点名** |

校验顺序：**结构 → 禁用字段 → 未知字段 → 字段值**。前两类是"请求本身不合规"，
失败得快，也让后面不必处理半成品数据。

### 3.2 登录 `POST /api/auth/login` → `validate_login()`

| 项 | 规则 |
| :--- | :--- |
| 请求体体积 | ≤ 2 KB |
| `account` | 必填，字符串 4—64 字符；归一化（去首尾空白，手机号去分隔符）后须匹配登录名格式**或**手机号格式 |
| `password` | 必填，字符串 8—64 字符 |
| 禁用字段 | `role`、`userId`、`iterations`、`salt`、`rememberMe` |
| 未知字段 | 一律 400 |

登录**不做强度判断**（不判全同字符、不判是否等于账号）：强度在注册时把关，
登录时多做一次格式拒绝会把本该 `401` 的情况变成 `400`，反而给攻击者多一个信号。
"账号不存在 / 口令错误 / 被锁定 / 被停用"四种情况回同一句话，由认证流程负责，
本层不参与——本层只保证不因为校验差异提前泄露其中任何一种。

### 3.3 退出 `POST /api/auth/logout` → `validate_logout()`

| 场景 | 结果 |
| :--- | :--- |
| 完全不传 body | 通过 |
| 传空对象 `{}` | 通过 |
| 传 body 且含任何字段（`userId`、`token`、`sessionId`…） | 400，不点名、不回显 |
| 请求体 > 1 KB | 413 |

撤销哪个会话由请求头里的令牌决定，因此这里不接受任何"指定会话"的参数——
多传参数本身就是探测行为。

### 3.4 本人信息 `GET /api/users/me` → `validate_me()`

不接受请求体（有体即 400）；查询参数忽略并记审计，返回被忽略的参数名列表供调用方
落审计。该接口的语义就是"令牌对应的人"，多传参数不改变结果。

### 3.5 错误结构

对外只允许 14 个错误码，本层产出其中三个：`VALIDATION_ERROR`(400)、
`PAYLOAD_TOO_LARGE`(413)、`INTERNAL_ERROR`(500)；令牌类错误码由鉴权中间件复用
同一个 `errors.py`。响应体最多四字段：

```json
{
  "code": "VALIDATION_ERROR",
  "message": "请求参数不合法",
  "traceId": "0f3c1b7e9a2d4c56",
  "details": [{ "field": "password", "reason": "TOO_LONG" }]
}
```

`details` 的四条硬约束（实现方式）：

1. `field` 必须是 ASCII 标识符，且只允许契约里写死的字段名或禁用字段名——
   **任意未知字段名不进 details**，因为名字由调用方构造，可能是 `' OR 1=1--`；
2. `reason` 只允许 `REQUIRED`、`TYPE_MISMATCH`、`TOO_SHORT`、`TOO_LONG`、
   `FORMAT_INVALID`、`OUT_OF_RANGE`、`NOT_ALLOWED`、`DUPLICATE`；
3. 不回显用户提交的原值（一份被拒的口令不应该出现在响应里被截图）；
4. `details` 最多 16 条，防止它被当成反射放大器。

## 4. 错误与日志里不出现什么

交付要求：「错误与日志不出现口令、派生值、密钥、栈信息」。做法是**三层兜底 +
一条收敛路径**：

| 层 | 机制 | 挡住什么 |
| :--- | :--- | :--- |
| 值级 | `Secret` 一创建就把明文登记进脱敏表，`repr`/`str`/f-string 全部返回 `<redacted>`；日志过滤器对已登记值做全文替换 | 有人 `logger.info("pwd=%s", pwd)` 或 `print(pwd)` |
| 键级 | 键名含 `password`/`token`/`salt`/`derived`/`hash`/`key`/`secret`/`signature` 的字段，值一律不输出 | 业务代码新增字段时忘记脱敏 |
| 形状级 | 正则匹配 `pbkdf2_sha256$...` 存储串、`Bearer xxx`、`password=...` 形态 | 从数据库读出来的派生值与令牌 |
| 收敛 | `handle_unexpected()` 只记**异常类型**与处理阶段，不记异常消息（常带 SQL 与字段值）、不记堆栈；对外只回 `{code, message, traceId}` | 500 响应带 `Traceback`、表名、SQL |

日志里**记**什么：`event`、`traceId`、`stage`、`fields=字段:原因`（如
`fields=password:TOO_SHORT,phone:FORMAT_INVALID`）、`count`、`exc_type`。
这些都是常量或安全标识符，不含用户值。未知字段只记**个数**，不记名字——
否则等于把攻击者构造的串写进日志，顺带污染日志解析。

`traceId` 用 `secrets.token_hex(8)` 生成，同一条请求里**日志与响应共用一个值**：
用户截图里的编号能在日志里查到对应记录（SR-19 的验收方式）。

审计与展示用 `mask_phone` / `mask_email` / `mask_account`（`138****8000`、
`ab***@example.com`），这三个函数不是加密，只是少露几位；限流键必须用哈希而不是
这些掩码值，那属于限流模块（R-D-06）。

## 5. 调用了第 5 周 `src/crypto/` 的哪个函数

| 环节 | 调用的函数 | 文件 | 参数与返回 |
| :--- | :--- | :--- | :--- |
| 注册 | `hash_password(password, *, iterations, salt, seed)` | `src/crypto/加盐哈希.py` L49–L71 | 返回 `pbkdf2_sha256$600000$<salt>$<derived>`；默认迭代 600000、盐 16 字节（`secrets.token_bytes`）、派生值 32 字节 |
| 登录 | `verify_password(password, stored)` | 同文件 L74–L95 | 返回 `bool`，内部用 `hmac.compare_digest` 常数时间比较 |
| 口径集中 | `password_port.hash_password()` / `verify_password()` / `split_stored()` / `parameters()` | `src/user/password_port.py` | 只做"按路径加载 + 参数读取 + 存储串切四列"，不实现任何算法 |

两个必须说清的细节：

1. **文件名带中文，不能 `import 加盐哈希`**。`password_port.py` 用
   `importlib.util.spec_from_file_location` 按路径加载，路径由
   `Path(__file__).parents[1] / "crypto" / "加盐哈希.py"` 算出，不依赖工作目录。
   组内其他人直接 `from password_port import hash_password` 即可，避免各写一份参数。
2. **口令派生只在第 5 周模块里做一次**（CTRL-05），业务代码不另写算法、不改迭代次数。
   `parameters()` 读的是第 5 周模块的模块级常量（`ALGO`、`DEFAULT_ITERATIONS`、
   `SALT_BYTES`、`DK_LEN`），改参数只能改源头那一个文件。

建库脚本要求的四列直接从存储串切出来，不接触明文：

```python
from password_port import hash_password, split_stored

stored = hash_password(validated.password)        # validated 来自 validate_register()
cols = split_stored(stored)
# cols == {"algo": "pbkdf2_sha256", "iterations": "600000",
#          "salt": "...", "derived": "..."}   → 落库的四列
```

口令明文到此为止：`Secret.reveal()` 只允许传给上面两个函数，不得进响应、日志、URL。

## 6. 已知局限

按"验收时会被问"的顺序写，每条都给出影响与后续归属，不藏。

| # | 局限 | 影响 | 后续 |
| :--- | :--- | :--- | :--- |
| 1 | 只判"请求是否合法"，不判"业务是否成立" | 合法格式的重复注册仍需数据层唯一约束兜底；账号是否存在也不在本层判断 | 数据地基 R-D-01、R-D-12 |
| 2 | 没有速率限制与失败计数 | 单次校验很快，本层挡不住高频探测；"10 次/15 分钟""锁定"都不在这里 | 后端平台 R-D-06、R-D-03 |
| 3 | 口令强度只有四条规则（长度、字节上限、非全同字符、不等于账号/手机号） | 不查弱口令字典与泄露库，`Password123` 这类口令能通过 | 后续如需可接 k-匿名弱口令查询 |
| 4 | 口令 256 字节上限在字符上限 64 之下**不会先触发**（UTF-8 单字符最多 4 字节，64×4=256） | 这条规则当前是冗余护栏 | 若将来放宽字符上限，它才开始生效 |
| 5 | 手机号只支持中国大陆 11 位；归一化只去空格与连字符 | `+8613800138000`、`(138)00138000` 会被判格式错；港澳台与国际号不支持 | 属产品范围问题，扩号段需同步改契约与正则 |
| 6 | 用户名限 ASCII（字母数字下划线），不支持中文昵称与邮箱登录 | 用户体验上的限制；换来的是没有同形字混淆 | 昵称走 `nickname` 字段，不参与登录 |
| 7 | 不做 Unicode 归一化（NFC/NFKC） | 视觉相同的口令（全角/半角、组合字符）字节不同，会被当成不同口令；反过来也不会误判为同一口令 | 当前不归一化是**有意的**：归一化会扩大等价口令集 |
| 8 | 脱敏依赖键名与已登记值 | 业务自造键名（`pwd1`、`pass`）不在名单里会漏；盐/派生值只有经过 `split_stored()` 才自动登记 | 新增字段时同步维护 `SENSITIVE_KEY_PARTS`；数据库读取路径统一走 `split_stored()` |
| 9 | 重复 JSON 键一律拒绝，不做"取最后一个"的兼容 | 某些网关重写 JSON 时可能引入重复键 | 若接入此类网关需重新评估 |
| 10 | 未知字段一律 400，对旧客户端不宽容 | 客户端多发一个字段就失败 | 这是契约"默认拒绝"的要求，不是缺陷 |
| 11 | 不校验 `Content-Length` 与实际字节是否一致 | 由 Web 服务器/框架负责；本层只按拿到的字节量判 | 部署层配置 |
| 12 | 未做渗透测试、未接真实数据 | 结论只覆盖本层逻辑，不含部署与环境 | 任务边界 |

接入业务代码的方式（伪代码，业务实现由组内其他成员完成）：

```python
from user import Secret, handle_unexpected, validate_login, validate_register
from user.errors import ApiError

def register_handler(raw_body: bytes, content_type: str, trace_id: str):
    try:
        data = validate_register(raw_body, content_type=content_type, trace_id=trace_id)
        stored = hash_password(data.password)        # 第 5 周函数，只在这一处调用
        user_id = save_user(data.username, data.phone, stored)   # 数据层，参数化
        return 201, {"userId": user_id, "username": data.username}
    except ApiError as exc:
        return exc.status, exc.to_response()          # traceId 与日志同一编号
    except Exception as exc:
        return 500, handle_unexpected(exc, stage="register", trace_id=trace_id)
```
