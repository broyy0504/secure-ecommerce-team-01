## 0. 结论速览

- 本模块实现的是**“为什么正确、代价多少”的原理演示**，不是可用的安全组件。
- 数学正确性已用**两条路径**核对：教科书公开向量 + 独立复算（第 10 节，24 项全部通过）。
- 与朴素方法相比，快速幂（重复平方乘）把模幂从 `O(e)` 降到 `O(log e)`：指数 `e=1048576` 时实测加速约 **3.2 万倍**（第 8 节）。
- 小位宽 RSA 的**根本缺陷是模数可被分解**：64 位模数用 Pollard ρ 实测 **约 144 ms** 即被攻破（第 9 节）。
- 口令哈希用 **PBKDF2-HMAC-SHA256**（600000 次迭代）：单次哈希约 **154 ms**，是单轮无盐 SHA-256（0.30 μs）的约 **5.1×10⁵ 倍**；随机盐保证同一口令两次哈希结果不同（第 5 节）。
- 因此本模块**不能承担任何真实数据的机密性**；生产必须使用标准密码库 + 足够密钥长度 + 正确填充 + CSPRNG，口令哈希改用 Argon2id 等内存硬化算法（第 9 节）。

## 2. 大整数的表示与来源（为什么没有单列一节）

任务书允许“直接使用语言内置的任意精度整数，把时间花在算法本身”。本组采纳该选项：

- **基础模块与 RSA 均以 Python 内置的任意精度整数 `int` 作为大整数载体**（见 `bigint_ops.py` 头注释）。
- 本组**未自行实现大整数的加、减、乘、除、比较**，因此按任务书约定，**不单列“大整数表示方法与复杂度”一节**。

为便于估算全文复杂度，给出该载体在**本模块规模（≤1024 位）**下的代价模型（`n` 为位宽，`M(n)` 为一次 `n` 位模乘开销）：

| 运算             | 采用算法             | 复杂度              |
|:-------------- |:---------------- |:---------------- |
| 加 / 减 / 比较     | 逐位（字）运算          | `O(n)`           |
| 乘法             | 教科书式（schoolbook） | `O(n²)`          |
| 除法 / 取模        | 长除法              | `O(n²)`          |
| 模乘 `a·b mod m` | 乘法 + 取模          | `O(n²)`，即 `M(n)` |

> 说明：这是全文复杂度分析统一使用的**上界模型**。CPython 的 `int` 在很大位宽下会切换到 Karatsuba 乘法，届时 `M(n)` 低于 `O(n²)`；本课题目标位宽（64 / 128 / 256，对比上限 1024）落在平方级区间，不影响结论。

## 3. 密码学基础算法模块（`bigint_ops.py`）

模块分四组能力：模运算基础、快速幂、gcd 与模逆、素性检测与素数生成。

### 3.1 模运算基础

| 方法                 | 语义                   | 关键约定                                                   |
|:------------------ |:-------------------- |:------------------------------------------------------ |
| `mod(a, m)`        | `a mod m` 的**非负**代表元 | 负数也返回非负结果：`mod(-1, 7) = 6`。密码学中必须用非负代表元，否则负数会破坏后续模乘正确性 |
| `mod_add(a, b, m)` | `(a + b) mod m`      | 结果恒在 `[0, m)`                                          |
| `mod_sub(a, b, m)` | `(a − b) mod m`      | 结果恒在 `[0, m)`                                          |
| `mod_mul(a, b, m)` | `(a × b) mod m`      | 结果恒在 `[0, m)`                                          |

**原理**：全部归一化到完整剩余系 `{0, 1, …, m−1}` 上运算。**参数理由**：模数必须为正整数（`_require_positive_modulus`），非法即抛 `ValueError`，遵循“非法输入明确拒绝而非静默出错”的模块级原则。

**复杂度**：`mod`/`mod_mul` 的取模为长除法，`O(n²)`；`mod_add`/`mod_sub` 仅需非负归一，`O(n)`。空间均 `O(n)`。

### 3.2 快速幂（模幂）—— 本模块的性能核心

**原理（重复平方乘）**：把指数写成二进制 `e = Σ bᵢ·2ⁱ`，则

```
base^e = Π base^(2^i)      （仅对所有 bᵢ = 1 的 i 求积）
```

顺序扫描 `e` 的每一位：为 `1` 时把当前平方项乘入结果，每轮把底数自乘一次。因此只需 `O(log₂ e)` 次模乘，而非 `O(e)` 次。

| 方法                            | 语义                     | 复杂度                                   |
|:----------------------------- |:---------------------- |:------------------------------------- |
| `mod_pow(base, exp, m)`       | `base^exp mod m`，重复平方乘 | 时间 `O(log e × M(n))`，空间 `O(n)`，迭代无递归栈 |
| `mod_pow_naive(base, exp, m)` | 逐次相乘 `exp` 次，**仅供对比**  | 时间 `O(e × M(n))`，空间 `O(n)`            |

**边界约定**：`exp = 0` 返回 `1 mod m`（含 `0⁰ = 1`）；`m = 1` 返回 `0`；底数先规范化到 `[0, m)`；负指数先求逆再按正指数计算（要求 `base` 与 `m` 互素，否则抛 `ArithmeticError`）。

**参数理由**：`mod_pow_naive` 仅作“为什么必须用快速幂”的实测对照，并被 `MAX_NAIVE_EXPONENT = 10⁷` 硬性封顶——朴素法 `O(e)`，指数过大会长时间占用 CPU，超出即抛异常，避免误用导致假死。

### 3.3 最大公约数与模逆

**原理**：`gcd` 用欧几里得算法；`ext_gcd` 用扩展欧几里得求满足 `a·x + b·y = gcd(a, b)` 的 `(x, y)`；`mod_inverse(a, m)` 复用 `ext_gcd`——当且仅当 `gcd(a, m) = 1` 时存在逆元，否则抛 `ArithmeticError`（**逆元存在 ⟺ 互素**）。

| 方法            | 复杂度                                                     | 边界                                   |
|:------------- |:------------------------------------------------------- |:------------------------------------ |
| `gcd`         | 时间 `O(log min(\|a\|,\|b\|))`（Lamé：最坏为相邻斐波那契数），空间 `O(n)` | `gcd(a,0)=\|a\|`、`gcd(0,0)=0`、负数取绝对值 |
| `ext_gcd`     | 同上，迭代实现（递归在大数下可能栈溢出）                                    | 保证返回 `g ≥ 0` 且 `a·x+b·y=g`           |
| `mod_inverse` | `O(log min(\|a\|, m))`                                  | `m=1` 约定逆元为 `0`；`gcd≠1` 抛异常          |

**参数理由**：RSA 的私钥指数 `d = e⁻¹ mod φ(n)` 与 CRT 参数 `qInv = q⁻¹ mod p` 都由 `mod_inverse` 支撑，故该实现对“不可逆”失败路径必须有明确、可断言的行为。

### 3.4 素性检测（Miller-Rabin）与随机素数生成

**原理**：把 `n−1` 写成 `n−1 = 2ˢ·d`（`d` 为奇数）。对见证 `a`，若 `n` 为素数则恒有 `a^d ≡ 1 (mod n)` 或存在 `0 ≤ r < s` 使 `a^(2ʳ·d) ≡ −1 (mod n)`。见证破坏该性质即可**断定 `n` 为合数**（无假阴性）；素数可能被误判为合数，概率不超过 `4⁻ᵏ`（`k` 为轮数），故称“概率素性”。

| 方法                                     | 行为                       | 复杂度                                                                                       |
|:-------------------------------------- |:------------------------ |:----------------------------------------------------------------------------------------- |
| `is_probable_prime(n, witnesses, rnd)` | 素性判定（见下“可复现性设计”）         | 时间 `O(k × log n × M(n))`，空间 `O(n)`                                                        |
| `random_prime(bit_length, rnd)`        | 生成恰好 `bit_length` 位的随机素数 | 期望试 `≈ 0.347 × bit_length` 个候选；时间 `O(bit_length × k × log n × M(n))`，空间 `O(bit_length)` 位 |

**可复现性设计（关键参数理由）**：`is_probable_prime` 以常量 `DETERMINISTIC_MR_BOUND ≈ 3.317 × 10²⁴` 为界——

- `n < 该上界`（**完整覆盖 64 位**，`2⁶⁴ ≈ 1.8 × 10¹⁹`）：改用固定的 12 个素数见证集 `{2,3,5,…,37}`，结论是**确定性**的，同一输入永远同一结果，不受随机源影响 → 测试可复现；
- `n ≥ 该上界`（如 **128 位**，`2¹²⁸ ≈ 3.4 × 10³⁸`）：退化为概率判定，误判率 `≤ 4⁻ᵏ`。

**`random_prime` 的参数理由**：候选由 `big_int(bit_length) | 2^(bit_length−1) | 1` 构造，分别保证“位长达标”与“为奇数”（直接排除一半候选）。**注意**：生成的素数必为奇数，故 `bit_length = 2` 只会得到 3，不会得到 2。

### 3.5 随机区间取样

**原理**：`random_in_range(lo, hi, rnd)` 采用**拒绝采样**——生成 `bits = (hi−lo+1).bit_length()` 位的随机数，落在区间外则重抽，直到命中再平移。

**参数理由**：拒绝采样替代“取模归约”，后者会使区间前段数值出现概率略高（**模偏差**），属密码学场景下的结构性缺陷。**复杂度**：时间 `O(n)` 期望（拒绝率 < 50%），空间 `O(n)`。

## 4. 小位宽 RSA（`rsa.py`）

`rsa.py` 实现**教科书式 RSA（Textbook RSA）**的完整流程，定位是：证明 RSA 运算“数学上为什么正确、代价是多少”，并作为**反面教材**论证“小位宽 RSA 为什么不能用于生产”。

| 能力         | 方法                                            |
|:---------- |:--------------------------------------------- |
| 密钥生成       | `generate_key_pair(bit_length, rnd)`          |
| 加密         | `encrypt(pub, m)`　→　`c = m^e mod n`           |
| 解密（直接）     | `decrypt(priv, c)`　→　`m = c^d mod n`          |
| 解密（CRT 加速） | `decrypt_crt(priv, c)`                        |
| 字符串 / 中文   | `encrypt_string` / `decrypt_string`（UTF-8 分块） |
| 字节流        | `encrypt_bytes` / `decrypt_bytes`             |

支持位宽 64 / 128 / 256（`MIN_BITLENGTH = 32`）。

### 4.1 数学基础

取素数 `p、q`，令 `n = p·q`，`φ(n) = (p−1)(q−1)`；选 `e` 使 `gcd(e, φ(n)) = 1`，令 `d = e⁻¹ mod φ(n)`。由**欧拉定理**，对任意与 `n` 互素的 `m`：

```
m^φ(n) ≡ 1 (mod n)   ⟹   m^(e·d) = m^(1 + k·φ(n)) ≡ m (mod n)
```

故 `(m^e)^d ≡ m (mod n)`——这是加解密互逆的全部依据。（`m` 与 `n` 不互素的少数情形，由中国剩余定理可证该式仍成立。）

### 4.2 密钥生成

```
1. p ← random_prime(bit_length/2)，q ← random_prime(bit_length − bit_length/2)，p ≠ q
2. n = p·q             （若 n 位宽 ≠ 目标位宽则重挑，保证模数“凑满”目标位宽）
3. φ(n) = (p−1)(q−1)
4. e ← 65537，若 gcd(e, φ(n)) ≠ 1 则依次退化为 3 / 5 / 17 / 257 / 从 3 起的奇数搜索
5. d = e⁻¹ mod φ(n)     （扩展欧几里得）
6. CRT 参数：dp = d mod (p−1)，dq = d mod (q−1)，qInv = q⁻¹ mod p
```

**为什么位宽要凑满**：`p、q` 最高位均为 1 时，`n` 位宽可能是目标值或目标值 −1，故循环重挑直到 `n.bit_length() == bit_length`。

**复杂度**：时间由素数搜索主导，期望 `O(bit_length × log n × M(n))`；空间 `O(bit_length)` 位。

### 4.3 加密与解密（整型）

```
加密：c = m^e mod n        （要求 0 ≤ m < n）
解密：m = c^d mod n        （要求 0 ≤ c < n）
```

二者都走 `bigint_ops.mod_pow`，但**指数规模不同**：`e` 常用 65537（仅 17 位），`d` 约与 `n` 等宽。这解释了“加密快、解密慢”。越界明文/密文（`<0` 或 `≥ n`）一律抛 `ValueError`。

### 4.4 CRT 加速（中国剩余定理）

由费马小定理，可在两个半宽模数上分别计算：

```
m1 = c^dp mod p
m2 = c^dq mod q
h  = qInv · (m1 − m2) mod p
m  = m2 + h · q
```

把“1 次全宽模幂”换成“2 次半宽模幂 + 合并”。模乘开销约 `O(b²)`（`b` 为位宽），故半宽模幂约 `(b/2)² = b²/4`，两次相加 `≈ b²/2`，再叠加小模数运算的常数优势，**理论加速比约 3~4 倍**（实测见第 8.3 节）。

### 4.5 字符串与中文明文的分块编码

RSA 只能加密 `[0, n)` 内的整数，无法直接加密任意长字符串。做法：

1. 按 `block_bytes = (n.bit_length()−1)//8 − 1` 切块（64 位 → 6 字节/块；128 位 → 14 字节/块；256 位 → 30 字节/块）；
2. 每块**前置 1 字节哨兵 `0x01`**，整体解释为整数后加密；
3. 解密时先还原整数、转字节，校验首字节为 `0x01` 后去掉哨兵，拼接得原文。

**为什么每块明文容量是 `floor((b−1)/8) − 1`**：`n` 为 `b` 位，故 `n ≥ 2^(b−1)`。任何不超过 `floor((b−1)/8)` 字节的非负整数都满足 `< 2^(8·floor((b−1)/8)) ≤ 2^(b−1) ≤ n`，必落入 `[0, n)`；再扣掉 1 字节哨兵即为每块明文容量。

**哨兵的两个作用**：① **保长度**——明文块若以 `0x00` 开头，整数转字节会丢失前导零，加哨兵后最高字节恒为 `0x01`，长度信息不丢失；② **做校验**——解密后首字节不是 `0x01`，说明密文被篡改或密钥不匹配，直接拒绝。

**复杂度**：`encrypt_string` 对 `L` 字节明文为 `O(⌈L/block_bytes⌉ × log e × M(n))`，空间 `O(L)`。

## 5. 加盐哈希演示（`加盐哈希.py`）

### 5.1 原理

口令存储与 RSA 的目标相反：**不是保密，而是不可逆**。`加盐哈希.py` 用 **PBKDF2-HMAC-SHA256** 做加盐、迭代次数可调的慢哈希：

```
DK = PBKDF2(PRF = HMAC-SHA256, P = 口令, S = 盐, c = 迭代次数, dkLen = 32)
```

- **盐（salt）**：每用户唯一的随机值，与哈希一同存储；盐无需保密。作用是把“相同口令 → 相同哈希”变为“相同口令 + 不同盐 → 不同哈希”，击穿彩虹表与跨用户批量破解。
- **迭代次数 `c`**：把单次哈希代价放大 `c` 倍，从而按同样倍数抬高“离线暴力枚举”的成本，这是慢哈希对抗暴力破解的核心手段。
- **HMAC**：PBKDF2 以 HMAC 作为伪随机函数，避免长度扩展等结构性问题。
- **不可逆**：哈希是单向函数，无法从存储值反推口令；与 RSA 的**可逆加密**本质不同。
- **常数时间比较**：验证用 `hmac.compare_digest` 比较派生密钥，避免逐字节短路比较带来的计时侧信道。

**存储格式（自描述）**：

```
pbkdf2_sha256$<iterations>$<salt_b64url>$<hash_b64url>
```

算法标识、迭代次数、盐与派生密钥全部写入同一字符串，便于**未来无损升级**：提高迭代次数或更换算法后，旧记录仍能凭自带参数校验。

**验证流程**：解析存储串 → 取回盐与迭代次数 → 用同一参数重算派生密钥 → 常数时间比较。

### 5.2 时间复杂度与空间复杂度

| 步骤                      | 时间复杂度                                                  | 空间复杂度               |
|:----------------------- |:------------------------------------------------------ |:------------------- |
| `hash_password`         | `O(c × H + len(口令) + len(盐))`，`H` 为一次 HMAC-SHA256 压缩开销 | `O(dkLen)`，即 `O(1)` |
| `verify_password`       | 同 `hash_password`（重算一次派生密钥 + 常数时间比较）                   | `O(dkLen)`          |
| `_make_salt`（`secrets`） | `O(SALT_BYTES)` 熵采样                                    | `O(SALT_BYTES)`     |
| `_make_salt`（固定种子）      | `O(SALT_BYTES)`，但**非密码学安全**（仅用于演示复现）                   | `O(SALT_BYTES)`     |

**要点**：耗时随迭代次数**线性增长**（`O(c)`），与口令长度近似无关；空间开销为**常数级**——PBKDF2 **不是内存硬化算法**，这正是它在生产中应被 Argon2id 取代的原因（见 9.1 节）。**与朴素方法的性能对比**见 8.5 节。

### 5.3 参数取值理由

| 参数                        | 取值                                   | 理由                                                             |
|:------------------------- |:------------------------------------ |:-------------------------------------------------------------- |
| 算法                        | PBKDF2-HMAC-SHA256                   | FIPS 认可、Python 标准库自带、无第三方依赖，适合教学；安全性弱于内存硬化算法（见 9.1 节）          |
| 迭代次数 `DEFAULT_ITERATIONS` | 600000                               | 对齐 OWASP 对 PBKDF2-HMAC-SHA256 的建议值，把离线枚举成本抬高约 5×10⁵ 倍（见 8.5 节） |
| 盐长度 `SALT_BYTES`          | 16 字节（128 位）                         | 满足 NIST SP 800-132 对盐 ≥ 128 位的要求；每用户唯一随机盐消除彩虹表与相同口令的碰撞         |
| 盐长度下限（校验）                 | 8 字节                                 | 代码对过短盐直接抛 `ValueError`，防止误用弱盐                                  |
| 派生密钥长度 `DK_LEN`           | 32 字节（256 位）                         | 与 SHA-256 输出等宽，抗碰撞、抗暴力枚举                                       |
| 存储格式                      | `pbkdf2_sha256$iterations$salt$hash` | 自描述，记录算法与参数，支持未来无损升级迭代次数/算法                                    |
| 口令比较                      | `hmac.compare_digest`                | 常数时间比较，避免计时侧信道                                                 |
| 演示用盐种子                    | `random.Random(seed)`                | 仅用于固定种子复现；**非密码学安全**，生产必须用 `secrets`（见 9.1 节）                  |

## 6. 时间复杂度与空间复杂度汇总

记 `n` 为模数位宽，`M(n) = O(n²)` 为一次 `n` 位模乘开销，`k` 为 Miller-Rabin 轮数。

### 6.1 基础算法模块

| 算法                         | 时间复杂度                        | 空间复杂度    |
|:-------------------------- |:---------------------------- |:-------- |
| `mod` / `mod_mul`          | `O(n²)`                      | `O(n)`   |
| `mod_add` / `mod_sub`      | `O(n)`                       | `O(n)`   |
| `mod_pow`（快速幂）             | `O(log e × M(n))`            | `O(n)`   |
| `mod_pow_naive`（朴素，仅对比）    | `O(e × M(n))`                | `O(n)`   |
| `gcd` / `ext_gcd`          | `O(log min(\|a\|, \|b\|))`   | `O(n)`   |
| `mod_inverse`              | `O(log min(\|a\|, m))`       | `O(n)`   |
| `is_probable_prime`（`k` 轮） | `O(k × log n × M(n))`        | `O(n)`   |
| `random_prime`（`b` 位）      | 期望 `O(b × k × log n × M(n))` | `O(b)` 位 |
| `random_in_range`          | `O(n)` 期望                    | `O(n)`   |

### 6.2 RSA

| 算法                         | 时间复杂度                               | 空间复杂度    | 备注                           |
|:-------------------------- |:----------------------------------- |:-------- |:---------------------------- |
| `generate_key_pair`（`b` 位） | 期望 `O(b × log n × M(n))`            | `O(b)` 位 | 由素数搜索主导（素数密度 `≈ 1/(0.69·b)`） |
| `encrypt`（`e=65537`）       | `O(log e × M(n))`，`log e = 17`      | `O(n)`   | 很快                           |
| `decrypt`（直接）              | `O(log d × M(n)) ≈ O(b × M(n))`     | `O(n)`   | 最慢                           |
| `decrypt_crt`              | 约直接法的 `1/4`                         | `O(n)`   | 2 次半宽模幂 + 合并                 |
| `encrypt_string`（`L` 字节）   | `O(⌈L/block_bytes⌉ × log e × M(n))` | `O(L)`   | 逐块                           |

### 6.3 加盐哈希

| 算法                                           | 时间复杂度                                          | 空间复杂度           |
|:-------------------------------------------- |:---------------------------------------------- |:--------------- |
| `hash_password` / `verify_password`（`c` 次迭代） | `O(c × H)`，`H` 为一次 HMAC-SHA256 压缩开销（与口令长度近似无关） | `O(dkLen)`      |
| `_make_salt`                                 | `O(SALT_BYTES)`                                | `O(SALT_BYTES)` |

> 详见 5.2 节。

## 7. 参数取值理由

> 本节覆盖**基础算法模块与 RSA** 的参数；**加盐哈希的参数见 5.3 节**。

| 参数           | 取值                        | 理由                                                                                         |
|:------------ |:------------------------- |:------------------------------------------------------------------------------------------ |
| 公开指数 `e`     | 65537 = 2¹⁶+1             | 二进制仅两个 1 → 模幂只需 16 次平方 + 1 次乘法；足够大以避开小指数攻击；是事实标准                                           |
| 密钥位宽         | 64 / 128 / 256            | 任务书允许范围；小位宽便于在秒级完成分解演示（教学需要）                                                               |
| `p`、`q` 位宽   | 各取约一半                     | 使 `n` 达到目标位宽，且两因子规模相当（避免小因子易被试除/分解）                                                        |
| 分块字节数        | `floor((b−1)/8) − 1`      | 保证“哨兵+明文”整体严格小于 `n`，同时尽量提高每块容量                                                             |
| 块内哨兵 | 固定 1 字节 `0x01` | 整数 ↔ 字节转换会丢掉前导 0，哨兵令块首恒非零以保住长度，并作为廉价的格式校验（见 4.5） |
| 随机源 | `JavaRandom`（LCG）+ 固定种子 | 精确复刻 Java 标准库 `Random` 的 48 位 LCG，故与既有 Java 向量逐位一致；教学取舍：换取“固定种子即可复现”。**代价是随机性不安全**（见第 9 节） |
| 素性判定 | Miller-Rabin，`< 3.317×10²⁴` 用确定性见证集 | 64 位及以下为**确定性**结论，保证测试可复现；128 位以上退化为概率判定（误判率 `≤ 4⁻ᵏ`） |
| 区间取样 | 拒绝采样 | 避免取模归约引入的模偏差 |
| `MAX_NAIVE_EXPONENT` | `10⁷` | 朴素法 `O(e)`，封顶防止误用导致 CPU 假死 |
| CRT 参数 | `dp`、`dq`、`qInv` 预计算 | 解密时免去每次求逆与全宽模幂，换取约 3~4 倍加速 |

## 8. 性能实测：与朴素方法的对比

### 8.1 快速幂 vs 朴素连续乘法（本模块核心对比）

同一模数下比较 `mod_pow`（重复平方乘，`O(log e)`）与 `mod_pow_naive`（逐次相乘，`O(e)`）。**数据来源**：本模块 `bigint_ops.py` 第 3.2 节自测输出（Python 3.13，纯解释器循环，两个实现同一语言，故比值反映**算法**而非语言运行时差异）；固定 64 位模数 `n = 18446744073709551557`，底数 `3`，取多次运行的**最优单次**值（快速幂 200 次，朴素 3 次）。

| 指数 `e`  | 快速幂     | 朴素连续乘法   | 加速比        |
| -------:| -------:| --------:| ----------:|
| 4096    | 1.40 μs | 0.298 ms | **213×**   |
| 65536   | 1.90 μs | 4.88 ms  | **2568×**  |
| 1048576 | 2.40 μs | 76.71 ms | **31962×** |

**读数**：指数每翻一倍，朴素法耗时约翻一倍（`O(e)`）；快速幂只多约一次模乘（`O(log e)`），故随指数增大，差距迅速拉开到 4 个数量级。RSA 的 `d` 动辄上百位，**只有快速幂才能让解密在可接受时间内完成，朴素法完全不可用**。

> 上表即 `python src/crypto/bigint_ops.py` 的直接输出。绝对耗时随机器与负载波动，但量级与增长趋势稳定。

### 8.2 快速幂耗时随指数位长的增长（验证 `O(log e)`）

固定 64 位模数，指数取 `2ᵇ − 1`，观察耗时随指数位长 `b` 的变化（同上环境与取值方式）：

| 指数位长 `b` | 快速幂耗时     | 相对上一档 |
| --------:| ---------:| -----:|
| 8        | 1.10 μs   | —     |
| 32       | 6.40 μs   | ×5.82 |
| 128      | 29.50 μs  | ×4.61 |
| 512      | 128.60 μs | ×4.36 |
| 2048     | 553.30 μs | ×4.30 |
| 4096     | 1.19 ms   | ×2.15 |

**读数**：位长每次 ×4，耗时约 ×4；位长 ×2（2048→4096）耗时约 ×2——**耗时随位长线性增长**，即随指数线性而非随数值指数增长，符合 `O(log e)`。

### 8.3 直接解密 vs CRT 解密

**数据来源**：模块自测输出（Python 3.13，`rsa.py` 第 5 节）。同一密钥取 `c = encrypt(pub, 123456789)`，各取 50 次最优值。

| 密钥位宽   | 直接解密      | CRT 解密    | 加速比   |
|:------ | ---------:| ---------:| -----:|
| 128 位  | 31.90 μs  | 26.00 μs  | 1.23× |
| 256 位  | 108.20 μs | 67.50 μs  | 1.60× |
| 512 位  | 612.70 μs | 224.00 μs | 2.74× |
| 1024 位 | 3.44 ms   | 1.24 ms   | 2.78× |

**读数**：位宽每次翻倍，直接解密耗时约 ×4（模乘 `O(b²)`）；CRT 把全宽模幂拆成两次半宽模幂，位宽越大加速比越接近理论 3~4 倍。位宽小时合并开销占比高、收益不明显——这正是“CRT 在中大位宽下才有意义”的直观体现。

### 8.4 加密 vs 解密（指数长度决定快慢）

| 操作  | 指数                | 耗时（128 位密钥，模块自测） |
|:--- |:----------------- | ----------------:|
| 加密  | `e = 65537`（17 位） | 3.10 μs          |
| 解密  | `d`（约 128 位）      | 31.90 μs         |

**读数**：同一密钥下加密比解密快一个数量级，差异完全来自指数位长——这解释了工程上为什么把公开指数取很小（65537）当作标准做法。

### 8.5 加盐哈希 vs 单轮无盐 SHA-256（口令哈希核心对比）

口令哈希的“朴素方法”是**单轮无盐哈希**（对每个口令直接算一次 SHA-256）：它极快，因而可被彩虹表与 GPU 并行秒破。慢哈希刻意把单次计算变贵，从而抬高暴力枚举成本。**数据来源**：本机 Python 3.13.7 标准库 `hashlib` 实测，取多次运行最优值。

| 方法                                       | 单次耗时          | 相对单轮 SHA-256 |
|:---------------------------------------- | -------------:| ------------:|
| SHA-256 单轮（无盐，朴素）                        | 0.30 μs       | 1×           |
| PBKDF2-HMAC-SHA256，1 次迭代                 | 2.20 μs       | 7×           |
| PBKDF2-HMAC-SHA256，1000 次迭代              | 255.70 μs     | 852×         |
| PBKDF2-HMAC-SHA256，100000 次迭代            | 25.69 ms      | 85633×       |
| PBKDF2-HMAC-SHA256，**600000 次迭代（脚本默认值）** | **154.16 ms** | **513874×**  |

**读数**：每 1000 次迭代约 256 μs，**耗时随迭代次数线性增长**（`O(c)`），验证 5.2 节的复杂度结论；默认 600000 次迭代使单次口令校验约 154 ms，约是朴素单轮哈希的 **5×10⁵ 倍**——离线暴力枚举的成本被按同样倍数抬高。代价是登录/注册每次都要付出这 154 ms，需在“抗破解”与“交互延迟”之间取值。

## 9. 安全边界（威胁建模输入）

本节是本模块作为**第 6 周威胁建模输入材料**的核心。逐条给出“威胁 → 证据 → 生产对策”，可直接映射到 STRIDE / 攻击树条目。

### 9.1 威胁清单

| #   | 威胁（对应 STRIDE / 攻击）                                   | 证据（本模块实测或代码事实）                                                      | 生产对策                                        |
|:--- |:---------------------------------------------------- |:------------------------------------------------------------------- |:------------------------------------------- |
| T1  | **模数可被分解** → 私钥泄露（Information Disclosure）            | 64 位模数 `n = 11387562574731347071` 用 Pollard ρ 在 **约 144 ms** 内分解出因子 | 密钥长度 `≥ 2048` 位（NIST 建议 3072 位，长期数据更长）      |
| T2  | **无填充 ⇒ 确定性** ⇒ 可字典比对、可被选择明文攻击（Spoofing / Tampering） | 同一明文两次加密得到**完全相同**的密文                                               | 加密用 RSA-OAEP，签名用 RSA-PSS，绝不裸用模幂             |
| T3  | **乘法同态性** ⇒ 无密钥即可操纵明文（Tampering）                     | 实测 `E(m1)·E(m2) mod n == E(m1·m2 mod n)`                            | 同上（OAEP 填充消除可利用的同态结构）                       |
| T4  | **计时侧信道** ⇒ 由解密耗时统计推断私钥比特（Information Disclosure）    | `mod_pow` 按指数位分支，运算次数与内存访问随密钥位变化                                    | 常数时间实现，或对密文做盲化（blinding）                    |
| T5  | **随机源非密码学安全** ⇒ 密钥可被推算（Spoofing）                     | 密钥生成用 `JavaRandom`（LCG），其输出序列可被观测后预测                                | 一律使用 CSPRNG（`os.urandom` / `secrets`）       |
| T6  | **素性判定概率化** ⇒ 可能放入合数（Tampering）                      | `n ≥ 3.317×10²⁴`（如 128 位）退化为概率判定，误判率 `≤ 4⁻ᵏ`                        | 用标准库素性检测并保留足够轮数；生产密钥用可信库生成                  |
| T7  | **哨兵不是完整性保护** ⇒ 篡改可被误接受（Tampering）                   | `0x01` 哨兵只做“首字节校验”，非 MAC；攻击者可构造合法哨兵的密文块                             | 需要完整性时用 AEAD（如 AES-GCM）或对消息先签名              |
| T8  | **自实现密码学** ⇒ 已知与未知实现缺陷（Elevation of Privilege）       | 本模块为教学实现，未做常数时间、未做填充、未做侧信道加固                                        | 委托给经审计的标准库（`cryptography` / `PyCryptodome`） |

### 9.2 口令哈希相关威胁（T9–T12）

| #   | 威胁（对应 STRIDE / 攻击）                                   | 证据（本模块实测或代码事实）                                                 | 生产对策                                           |
|:--- |:---------------------------------------------------- |:-------------------------------------------------------------- |:---------------------------------------------- |
| T9  | **离线暴力枚举 / 字典攻击**（Spoofing）                          | 600000 次迭代把单次校验抬到约 154 ms；若改用单轮 SHA-256 则仅 0.30 μs，可被 GPU 并行秒破 | 保持足够迭代次数（≥ OWASP 建议）；改用 Argon2id 等内存硬化算法       |

### 9.3 一句话回答验收提问“这段代码能不能用到我们项目里”

> **不能。** 本模块是算法原理演示：它证明了 RSA 加解密为什么正确、代价是多少，但不具备任何工程安全性——小位宽可被秒级分解、无填充可被选择明文攻击、非常数时间存在计时侧信道、随机源非密码学安全。项目中真正的密钥与口令存储，必须委托给标准密码库并使用足够长的密钥与正确填充。

**哈希与加密的分工边界**：口令存储属于**哈希**问题（加盐不可逆），RSA 属于**公钥加密**（可逆），是两套机制。`src/crypto/加盐哈希.py` 演示了需求基线中“密码加盐不可逆存储”（`password_hash`，建议 Argon2id）的原理；生产实现必须使用经过审计的密码库与内存硬化算法，不要自行实现。

- 单块密文：K1 下 `m = 2 / 42 / n−1` 的密文与往返；3233 经典向量 `65^17 ≡ 2790`、`2790^2753 ≡ 65`；

## 11. 结论

- **正确性**：RSA 加解密结果可复现（固定种子 → 固定密钥 → 固定密文），并与教科书公开向量、独立复算双重核对一致。
- **复杂度**：快速幂 `O(log e × M(n))`、`gcd`/`mod_inverse` `O(log min)`、素性判定 `O(k × log n × M(n))`、CRT 解密约直接法的 `1/4`；空间均为多项式级（`O(n)` 位）。
- **性能**：指数 `1048576` 时快速幂比朴素法快约 **3.2 万倍**；1024 位下 CRT 解密比直接法快约 **2.8 倍**。
- **口令哈希**：PBKDF2-HMAC-SHA256（600000 次迭代）使单次校验约 **154 ms**，是单轮无盐 SHA-256 的约 **5×10⁵ 倍**；随机盐保证相同口令得到不同哈希。其价值在于抬高离线暴力破解成本，而非保密。
- **安全边界**：本模块的一切设计（小位宽、无填充、非常数时间、非安全随机源、非内存硬化哈希）都为教学复现服务，**不能承担真实数据的机密性**；生产实现必须使用标准密码库 + 足够密钥长度 + 正确填充 + CSPRNG，口令哈希改用 Argon2id。相关威胁条目见第 9.1、9.2 节，作为威胁建模的直接输入。

**本文所有数据均为实测值或代码事实，未经修饰。本模块为教学示例，仅用于教学，不得用于任何真实数据。**
