## 1. 模块概述

`rsa.java` 实现**教科书式 RSA（Textbook RSA）**的完整流程，定位为：

1. 证明 RSA 的加解密"数学上为什么正确"，以及它的运算代价；
2. 作为**反面教材**，论证"小位宽 RSA 为什么不能用于生产"（供第 6 周威胁建模使用）。

提供的能力：

| 能力 | 方法 | 说明 |
| :--- | :--- | :--- |
| 密钥生成 | `generateKeyPair(bitLength, rnd)` | 产出 p、q、n、φ(n)、e、d，并预计算 CRT 参数 |
| 加密 | `encrypt(pub, m)` | `c = m^e mod n` |
| 解密（直接） | `decrypt(priv, c)` | `m = c^d mod n` |
| 解密（CRT 加速） | `decryptCRT(priv, c)` | 中国剩余定理，约 3~4 倍提速 |
| 字符串/中文 | `encryptString` / `decryptString` | UTF-8 分块，支持任意长度与中文 |
| 字节流 | `encryptBytes` / `decryptBytes` | 底层分块编解码 |

支持位宽：64 / 128 / 256 位（`MIN_BITLENGTH = 32`），示例以 64、128 位为主，性能对比扩展到 1024 位。

依赖 `bigint_ops` 的 `modPow`（快速幂）、`modInverse`（扩展欧几里得求模逆）、
`randomPrime`（Miller-Rabin 素性检测 + 随机素数生成）。

## 2. 原理

### 2.1 RSA 的数学基础

取两个大素数 p、q，令 n = p·q，φ(n) = (p−1)(q−1)。选 e 满足 gcd(e, φ(n)) = 1，
令 d = e⁻¹ mod φ(n)。由**欧拉定理**，对任意与 n 互素的 m：

```
m^(φ(n)) ≡ 1 (mod n)   ⟹   m^(e·d) = m^(1 + k·φ(n)) ≡ m (mod n)
```

因此 `(m^e)^d ≡ m (mod n)`——这就是 RSA 加解密互逆的全部依据。
（对 m 与 n 不互素的少数情形，由中国剩余定理可证该式仍成立。）

### 2.2 密钥生成

```
1. p ← 随机素数(bitLength/2),  q ← 随机素数(bitLength/2),  p ≠ q
2. n = p·q            （模数，公开）
3. φ(n) = (p−1)(q−1)
4. e ← 65537，若 gcd(e, φ(n)) ≠ 1 则退化为 3/5/17/257/奇数搜索
5. d = e⁻¹ mod φ(n)   （扩展欧几里得）
6. CRT 参数：dp = d mod (p−1)，dq = d mod (q−1)，qInv = q⁻¹ mod p
```

**为什么位宽要凑满**：p、q 的最高位均为 1 时，n 的位宽可能是目标值或目标值−1，
代码中循环重挑直到 `n.bitLength() == bitLength`。

### 2.3 加密与解密

```
加密：c = m^e mod n          （m ∈ [0, n)）
解密：m = c^d mod n
```

二者都由 `bigint_ops.modPow`（重复平方乘）实现，但指数规模不同：
e 常用 65537（仅 17 位），d 约与 n 等宽。这解释了为什么**加密快、解密慢**。

### 2.4 CRT 加速（可选，已实现）

由费马小定理，可在两个半宽模数上分别计算：

```
m1 = c^dp mod p
m2 = c^dq mod q
h  = qInv · (m1 − m2) mod p
m  = m2 + h · q
```

因 dp、dq 各只有 d 的一半位长，把"1 次全宽模幂"换成"2 次半宽模幂 + 合并"。
模乘开销约 O(b²)（b 为位宽），故半宽模幂开销约 (b/2)² = b²/4，
两次相加 ≈ b²/2，再加上小整数合并的开销，**理论加速比约 3~4 倍**（实测见第 4 节）。

### 2.5 字符串与中文明文的分块编码

RSA 只能加密 `[0, n)` 内的整数，无法直接加密任意长字符串。本模块的做法：

1. 把明文字节串按 `blockBytes = floor((n.bitLength()−1)/8) − 1` 切块；
   - 64 位 → 6 字节/块，128 位 → 14 字节/块，256 位 → 30 字节/块；
2. 每个分块**前置 1 字节 `0x01` 哨兵**，整体解释为 BigInteger 后加密；
3. 解密时先还原 BigInteger，再转字节，校验首字节为 `0x01` 后去掉哨兵，拼接得到原文。

**哨兵的作用**（两个）：
- **保长度**：明文块若以 `0x00` 开头，`BigInteger` 转字节时会丢失前导零，
  加哨兵后最高字节恒为 `0x01`，长度信息不丢失；
- **做校验**：解密后首字节不是 `0x01`，说明密文被篡改或密钥不匹配，直接拒绝。

中文用例 `"在线书店"`（UTF-8 12 字节）在 64 位密钥下恰好切成 2 块，
往返完全一致，证明多字节字符与分块边界都能正确处理。

## 3. 时间复杂度与空间复杂度

设 n 为模数位宽，`M(n)` 为 n 位模乘开销（`BigInteger` 下约 O(n²)）。

| 算法 | 时间复杂度 | 空间复杂度 | 备注 |
| :--- | :--- | :--- | :--- |
| `generateKeyPair`（b 位） | 期望 O(b × log n × M(n)) | O(b) 位 | 由素数搜索主导（素数密度 ≈ 1/(0.69·b)） |
| `encrypt`（e=65537） | O(log e × M(n)) = O(17 × M(n)) | O(n) | e 仅 17 位，很快 |
| `decrypt`（直接） | O(log d × M(n)) ≈ O(b × M(n)) | O(n) | d 约 b 位，最慢 |
| `decryptCRT` | 约直接法的 1/4 | O(n) | 2 次半宽模幂 + 合并 |
| `encryptString`（L 字节） | O(⌈L/blockBytes⌉ × log e × M(n)) | O(L) | 逐块加密 |

`bigint_ops` 中与 RSA 相关的基础运算复杂度：

| 算法 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| `modPow`（快速幂） | O(log e × M(n)) | O(n) |
| `modPowNaive`（朴素连续乘法，仅对比用） | O(e × M(n)) | O(n) |
| `modInverse` / `extGcd` | O(log min(\|a\|, m)) | O(n) |
| `isProbablePrime`（k 轮） | O(k × log n × M(n)) | O(n) |

## 4. 性能实测数据

### 4.1 直接解密 vs CRT 解密（RSA 核心对比）

同一密钥，取 `c = encrypt(pub, 123456789)`，各取 50 次最优值（Temurin 17.0.20）：

| 密钥位宽 | 直接解密 | CRT 解密 | 加速比 |
| :--- | :--- | :--- | :--- |
| 128 位 | 47.30 μs | 37.70 μs | 1.25× |
| 256 位 | 117.90 μs | 83.20 μs | 1.42× |
| 512 位 | 620.80 μs | 257.20 μs | 2.41× |
| 1024 位 | 3.33 ms | 1.09 ms | 3.05× |

**读数**：位宽每次翻倍，直接解密耗时约 ×4（模乘 O(b²)）；CRT 把全宽模幂拆成
两次半宽模幂，位宽越大、加速比越接近理论的 3~4 倍。位宽小时 CRT 的合并开销占比高，
收益不明显——这也是"CRT 在中大位宽下才有意义"的直观体现。

### 4.2 加密 vs 解密（指数长度决定快慢）

| 操作 | 指数 | 耗时（128 位密钥） |
| :--- | :--- | :--- |
| 加密 | e = 65537（17 位） | 3.60 μs |
| 解密 | d（约 128 位） | 47.30 μs |

**读数**：同一密钥下加密比解密快一个数量级，差异完全来自指数位长——
这解释了工程上为什么把"公开指数取很小"（65537）当作标准做法。

### 4.3 与朴素方法对比（引自 `bigint_ops.java`）

快速幂模幂 vs 朴素连续乘法（同一 64 位模数）：

| 指数 e | 快速幂 | 朴素连续乘法 | 加速比 |
| :--- | :--- | :--- | :--- |
| 4096 | 微秒级 | 毫秒级 | 约 10²~10³ 倍 |
| 65536 | 微秒级 | 毫秒级 | 更大 |
| 1048576 | 微秒级 | 秒级 | 更大 |

**读数**：朴素法复杂度 O(e)，指数每翻倍耗时翻倍；快速幂 O(log e)，指数翻倍只多约一次模乘。
RSA 的 d 动辄上百位，**只有快速幂才能让解密在可接受时间内完成**，朴素法完全不可用。
（完整逐档数据见 `bigint_ops.java` 的 `section3Performance()` 输出。）

## 5. 参数取值理由

| 参数 | 取值 | 理由 |
| :--- | :--- | :--- |
| 公开指数 e | 65537 = 2¹⁶+1 | 二进制仅两个 1 → 模幂只需 16 次平方 + 1 次乘法；且足够大以避开小指数攻击；是事实标准 |
| 位宽 | 64 / 128 / 256 | 任务书允许范围；小位宽便于在秒级完成分解演示（教学需要） |
| p、q 位宽 | 各取约一半 | 使 n 达到目标位宽，且两因子规模相当（避免小因子易被试除） |
| 分块字节数 | `floor((b−1)/8) − 1` | 保证"哨兵+明文"整体严格小于 n，同时尽量提高每块容量 |
| 随机源 | `java.util.Random` + 固定种子 | 教学取舍：换取"固定种子即可复现"。**代价是随机性不安全**（见第 6 节） |
| 素性判定 | Miller-Rabin，< 3.3×10²⁴ 用确定性见证集 | 64 位及以下为**确定性**结论，保证测试可复现；128 位以上退化为概率判定（误判率 ≤ 4⁻ᵏ） |

## 6. 安全边界（最重要的部分）

### 6.1 小位宽 RSA 为什么不能用于生产

**① 模数可被分解（根本缺陷）。** 实测用 Pollard ρ 分解 64 位模数
`n = 11387562574731347071`，仅 **71.88 ms** 就得到因子。分解出 p、q 后，
φ(n) 和 d 可直接算出，私钥即刻泄露。2048 位 RSA 的分解难度约 2¹¹² 倍于 1024 位，
当前算力不可行；64 位则形同虚设。

**② 无填充 ⇒ 确定性 ⇒ 可被选择明文攻击。** 实测同一明文两次加密得到**完全相同**的密文。
攻击者可用"加密字典"比对已知明文，或利用**乘法同态性**：

```
E(m1) · E(m2) mod n == E(m1 · m2 mod n)
```

无需私钥即可让明文可预测地变化。此外还有低指数广播攻击、小消息攻击等。

**③ 实现存在计时侧信道。** `modPow` 按指数二进制位分支（为 1 才多做一次模乘），
运算次数与内存访问随密钥位变化；攻击者可通过精确测量解密耗时统计推断私钥比特（Kocher 1996）。

**④ 随机源不满足密码学安全。** 密钥生成用 `java.util.Random`，其输出序列可被观测后预测，
用于生成密钥会使私钥可被推算。本模块保留它是为了固定种子复现，属明确的教学取舍。

### 6.2 生产环境应当如何做

1. **密钥长度**：RSA ≥ 2048 位（NIST 建议 3072 位，长期数据更长）；
2. **填充**：加密用 **RSA-OAEP**，签名用 **RSA-PSS**，绝不裸用模幂；
3. **实现**：委托给经审计的标准密码库（JDK JCA / BouncyCastle），
   不要自行实现密钥生成、填充与常数时间运算；
4. **随机数**：一律使用 CSPRNG（`java.security.SecureRandom`）；
5. **常数时间**：解密使用常数时间实现，或对密文做盲化（blinding）。

### 6.3 一句话回答验收提问"这段代码能不能用到你们项目里"

> **不能。** 本模块是算法原理演示：它证明了 RSA 加解密为什么正确、代价是多少，
> 但不具备任何工程安全性——小位宽可被秒级分解、无填充可被选择明文攻击、
> 非常数时间存在计时侧信道、随机源非密码学安全。项目中真正的密钥与密码存储，
> 必须委托给标准密码库并使用足够长的密钥与正确填充（本项目口令存储另见 `hash_demo` 的加盐哈希方案）。
