## 3. P0 核心接口（已定义字段）

### 3.1 API-USER-001 注册买家账号

| 项目 | 内容 |
| --- | --- |
| 方法与路径 | `POST /api/users/register` |
| 参与者与鉴权 | 未注册访客；公开接口，必须限流并防重复提交 |
| 请求体 | `RegisterRequest`（`username`、`phone`、`password`，全部必填，`additionalProperties: false`） |
| 成功响应 | `201` + `UserPublic`（最小公开资料） |
| 失败响应 | `400` 参数不合法／`409` 登录名或手机号冲突／`429` 限流／`500` 服务异常 |
| 关键约束 | 登录名 `^[A-Za-z0-9_]{4,32}$`；手机号 `^1[3-9][0-9]{9}$`；密码 8–64 位，加盐不可逆存储；**注册响应不得包含密码或哈希** |
| 编号追踪 | UC-USER-001；FR-USER-001；SR-DATA-001、SR-SQL-001、SR-INPUT-001；NFR-REL-001 |
| 验收要点 | 提交合法登录名与密码可注册成功；重复登录名返回 `409`；用抓包检查响应体不含密码或哈希 |

### 3.2 API-AUTH-001 登录

| 项目 | 内容 |
| --- | --- |
| 方法与路径 | `POST /api/auth/login` |
| 参与者与鉴权 | 已注册且账号可用的内部角色；公开接口 |
| 请求体 | `LoginRequest`（`account`、`password`） |
| 成功响应 | `200` + `LoginResponse`（`accessToken`、`tokenType`、`expiresIn`、`user`），响应头带 `Cache-Control: no-store` |
| 失败响应 | `400`／`401` 凭据无效／`423` 账号锁定／`429` 限流／`500` |
| 关键约束 | 参数在服务端校验；失败提示统一为「账号或密码错误」，**不泄露账号是否存在或是否被锁定**；商户、管理员未通过审核或被停用时拒绝登录；令牌不得写入日志 |
| 编号追踪 | UC-USER-002；FR-USER-002；SR-INPUT-001、SR-AUTH-002、SR-LOG-001 |
| 验收要点 | 正确凭据能登录并拿到令牌；错误凭据不得建立会话；同一账号连续失败达阈值后返回 `423` |

> **待评审确认的数值冲突**：本草案按 `SR-AUTH-002`「同一账号连续登录失败 **5** 次必须锁定」执行，
> 而`功能需求清单V1.md` 的 `FR-USER-007` 写的是「连续输入错误 **10** 次后冻结 15 分钟」。
> 两处阈值不一致，需在评审会上统一为单一数值，本草案随之同步。
> （`FR-USER-007` 只出现在本说明中，未写入 OpenAPI 的 `x-trace`，待数值统一后再挂接。）

### 3.3 API-AUTH-002 退出

| 项目 | 内容 |
| --- | --- |
| 方法与路径 | `POST /api/auth/logout` |
| 参与者与鉴权 | 已登录用户；需要有效登录凭据 |
| 请求体 | 无 |
| 成功响应 | `204 No Content` |
| 失败响应 | `401`／`500` |
| 关键约束 | 退出成功后**原令牌立即失效**；重复退出按幂等处理，不影响其他设备或用户；记录操作结果但不记录令牌内容 |
| 编号追踪 | UC-USER-004；FR-USER-003；SR-SESSION-001、SR-LOG-001 |
| 验收要点 | 退出后拿原令牌访问受保护接口，应返回 `401 AUTH_UNAUTHENTICATED` |

### 3.4 API-USER-002 查询本人信息

| 项目 | 内容 |
| --- | --- |
| 方法与路径 | `GET /api/users/me` |
| 参与者与鉴权 | 已登录买家、商户或管理员；**本人数据范围** |
| 请求体 | 无（**没有任何标识用户身份的请求参数**） |
| 成功响应 | `200` + `UserProfile` |
| 失败响应 | `401`／`403`／`500` |
| 关键约束 | 用户身份只从服务端令牌解析，不接受客户端指定用户编号；响应字段按当前角色最小化返回；手机号、邮箱脱敏展示；不返回密码或哈希 |
| 编号追踪 | UC-USER-003；FR-USER-004；SR-AUTH-001、SR-LOG-001 |
| 验收要点 | 只返回本人资料且敏感字段脱敏；改请求里的用户编号不影响返回结果，越权访问返回 `403` |

### 3.5 API-USER-003 修改本人信息

| 项目 | 内容 |
| --- | --- |
| 方法与路径 | `PUT /api/users/me` |
| 参与者与鉴权 | 已登录用户；本人数据范围 |
| 请求体 | `UpdateProfileRequest`，**白名单字段**：`nickname`、`email`、`phone` |
| 成功响应 | `200` + `UserProfile`（更新后） |
| 失败响应 | `400`／`401`／`403`／`500` |
| 关键约束 | `additionalProperties: false`；`userId`、`role`、`status` 即使被提交也必须被服务端忽略或拒绝；手机号、邮箱做格式与归属校验；敏感资料变更记录审计信息 |
| 编号追踪 | UC-USER-005；FR-USER-005；SR-INPUT-001、SR-AUTH-001、SR-LOG-001 |
| 验收要点 | 仅白名单字段可改；提交 `role: admin` 不生效；越权改动他人资料返回 `403` |

> **编号前置依赖**：本接口关联 `FR-USER-005`「修改个人资料」，该编号沿用 V0.1 的映射，
> 与`功能需求清单V1.md`（该文件把 `FR-USER-005` 定义为改密码）存在错位，需随编号统一一并核定。

## 4. P1 场景接口（已定义字段）

本组场景为在线书店，「浏览图书并加入购物车」是第 3 周确定的扩展流程，本条链路 4 个接口本版一并细化。

| 编号 | 方法与路径 | 用途 | 参与者与鉴权 | 编号追踪 |
| --- | --- | --- | --- | --- |
| API-BOOK-001 | `GET /api/books` | 分页浏览和搜索在售图书 | 公开只读（未登录亦可） | UC-BOOK-001；FR-GOODS-001；NFR-PERF-001 |
| API-BOOK-002 | `GET /api/books/{bookId}` | 查询单本图书详情 | 公开只读 | UC-BOOK-002；FR-GOODS-002 |
| API-CART-001 | `GET /api/cart` | 查询当前买家的购物车 | 已登录买家；仅本人购物车 | UC-CART-001；FR-CART-001；SR-AUTH-001 |
| API-CART-002 | `POST /api/cart/items` | 将指定在售图书加入购物车 | 已登录买家；仅本人购物车 | UC-CART-002；FR-CART-002；SR-AUTH-001、SR-INPUT-001 |

关键约束：

- `GET /api/books`：`size` 上限 50，避免一次拉取全量数据；只返回在售图书；不暴露商户内部数据。
- `GET /api/books/{bookId}`：不区分「图书不存在」与「无权限」，统一返回 `404`，避免泄露内部状态；价格与库存只作为服务端权威数据展示。
- `GET /api/cart`：购物车归属只从登录身份获取，不接受客户端传入其他用户编号；金额以服务端商品价格计算；失效或不可售条目返回 `available: false` 并附原因。
- `POST /api/cart/items`：只允许提交 `bookId` 与 `quantity`，**不得信任客户端提交的价格、总价或归属用户编号**；校验图书状态、库存与购买数量。

## 6. 通用约定（沿用 V0.1，本版细化）

1. **基础路径与编码**：统一 `/api` 前缀；请求与响应默认 `application/json`，字符编码 UTF-8。
2. **传输安全**：除本地开发环境外，所有接口必须通过 HTTPS/TLS 访问；**密码和令牌不得出现在 URL 查询参数中**。
3. **身份来源**：登录成功后由后端签发访问令牌（`Authorization: Bearer <token>`）；受保护接口从令牌解析当前用户，不信任客户端提交的 `userId`、`role` 或资源归属字段。
4. **鉴权原则**：后端同时校验角色权限与资源归属，遵循默认拒绝、最小权限、对象级隔离。前端隐藏入口不能代替后端鉴权。
5. **数据最小化**：接口不得返回明文密码、密码哈希、密钥、完整支付凭证或与当前业务无关的个人信息。
6. **输入校验**：所有请求参数在服务端校验；请求体 schema 一律 `additionalProperties: false`，未知字段不落库；数据库查询必须参数化，不能拼接用户输入。
7. **金额表示**：金额使用字符串承载（如 `"45.00"`），避免二进制浮点误差；币种默认 `CNY`。
8. **审计追踪**：登录、退出、密码修改、鉴权失败和敏感操作记录操作人、时间、对象、结果与请求追踪编号；日志不得记录密码或令牌。
9. **请求追踪**：所有错误响应返回 `traceId`，与审计日志关联，便于第 6 周威胁建模和问题定位。

## 7. 状态码与错误语义

| 状态码 | 使用场景 | 业务错误码示例 | 约束 |
| --- | --- | --- | --- |
| `200 OK` | 查询、修改、登录成功 | — | 返回必要业务结果，不返回敏感字段 |
| `201 Created` | 注册成功 | — | 只返回资源标识与最小公开资料 |
| `204 No Content` | 退出成功 | — | 无响应体 |
| `400 Bad Request` | 参数缺失、格式错误、非法状态 | `VALIDATION_ERROR` | 返回字段级提示，不返回堆栈 |
| `401 Unauthorized` | 未登录、凭据无效、会话失效 | `AUTH_INVALID_CREDENTIALS`、`AUTH_UNAUTHENTICATED` | 登录失败提示不得泄露账号是否存在 |
| `403 Forbidden` | 已登录但角色或资源归属校验不通过 | `AUTH_FORBIDDEN` | 后端拒绝并记录越权尝试，不依赖前端拦截 |
| `404 Not Found` | 资源不存在或按安全策略隐藏越权资源 | `RESOURCE_NOT_FOUND` | 不得泄露其他用户、商户或内部资源信息 |
| `409 Conflict` | 登录名、手机号等唯一信息冲突 | `USER_ALREADY_EXISTS` | 给出可操作提示 |
| `423 Locked` | 连续登录失败导致账号锁定 | `AUTH_ACCOUNT_LOCKED` | 锁定阈值须与安全需求最终数值一致 |
| `429 Too Many Requests` | 超过限流阈值 | `RATE_LIMITED` | 防暴力破解与批量注册 |
| `500 Internal Server Error` | 未预期服务异常 | `INTERNAL_ERROR` | 只返回统一友好提示与 `traceId`，不暴露堆栈或数据库信息 |

统一错误响应结构：`{ code, message, traceId, details? }`。
`code` 是稳定业务错误码，供前端分支处理，不随文案变化；`message` 面向用户，不得泄露敏感状态。

   因此本说明第 3～8 节与 OpenAPI 的 `x-trace` 均只覆盖 9 个已定义操作，该接口的编号不进入机器可读追踪，
   待评审定论后一并挂接。
2. **登录失败锁定阈值**：`SR-AUTH-002` 为 5 次，`FR-USER-007` 为 10 次且冻结 15 分钟，两处数值需统一。
3. **FR/UC 编号最终归属**：本草案沿用 V0.1 的映射，与`功能需求清单V1.md` 存在错位（尤其 `FR-USER-003`～`006`）。编号以评审定稿为准，定稿后本文件、需求追踪矩阵与 API 清单须同步修正。
4. **登录凭据形态**：服务端会话还是访问令牌。本版按访问令牌（`Bearer`）编写，影响响应头与失效机制，但不影响 API 对象边界。
5. **注册唯一标识**：用户名、手机号还是二者组合。本版按「用户名 + 手机号均为唯一」编写。
6. **金额字段的传输格式**：本版用字符串避免浮点误差；若后端统一用整数分，需同步修改 `Money` 与相关示例。
