## 1. 结论先写

订单有**两个**标识，职责不同，都不能省：

| 标识 | 名称 | 类型 | 谁看得见 | 作用 |
| :--- | :--- | :--- | :--- | :--- |
| 主键 | `order_id` | `BIGINT UNSIGNED`（MySQL）／`INTEGER`（SQLite） | 只在库内、只在内部接口 | 数据库主键、外键引用、事务定位 |
| 对外编号 | `order_no` | `CHAR(20)` | 买家、商户、支付机构、对账文件 | 展示、查询、对账、幂等去重 |

**不允许合并成一个。** 用自增主键当对外编号，等于把"系统里一共有多少单、每单什么时候下的"
直接送给调用方，并且给编号遍历（T-ID-04）提供完美入口——改一个数字就能试别人的订单。
反过来，只留随机编号当主键会让索引变宽、外键变慢，也不适合做范围扫描。

## 2. `order_id`

| 项 | 定义 |
| :--- | :--- |
| 名称 | `order_id`（**不是** `id`、**不是** `orderId`、**不是** `order_sn`） |
| MySQL 类型 | `BIGINT UNSIGNED NOT NULL AUTO_INCREMENT` |
| SQLite 类型 | `INTEGER PRIMARY KEY AUTOINCREMENT` |
| 语义 | 全局唯一、单调递增、无业务含义 |
| 对外暴露 | **不暴露**。任何接口都不得返回 `order_id`；接口里的 `orderId` 字段值是 `order_no` 的字符串形式（见 §4 说明） |
| 不变式 | II 阶段不得改成 UUID / 字符串 / 复合主键；不得复用（删除后自增值不回退） |

> 关于命名冲突的提醒：`docs/design/03-接口契约.md` §4.5 的响应字段叫 `orderId`，
> 而它的示例值 `"20001"` 是**对外编号**。本文件把这件事说清楚：**库里的 `order_id` 与接口里的
> `orderId` 不是同一个东西**，接口的 `orderId` 承载的是 `order_no`。II 阶段实现时按此执行，
> 不要为了"名字一致"把自增主键暴露出去。

## 3. `order_no`

| 项 | 定义 |
| :--- | :--- |
| 名称 | `order_no` |
| 类型 | `CHAR(20)`（定长，ASCII），唯一索引 |
| 结构 | `CB` + `YYYYMMDD`（8 位，UTC 日期）+ 10 位 Crockford Base32 随机串 = 20 字符 |
| 正则 | `^CB[0-9]{8}[0-9A-HJKMNP-TV-Z]{10}$`（Crockford Base32 去掉 I、L、O、U，避免与 1、0 混淆） |
| 示例 | `CB20261110K7F3Q9M2XT` |
| 随机源 | CSPRNG（`secrets`），10 位 Base32 ≈ 50 位熵；同一毫秒内碰撞概率可忽略，且有唯一索引兜底 |
| 可预测性 | **不可预测**：不含自增序号、不含用户标识、不含金额；连续两单的编号之间没有可推导关系 |
| 生成位置 | 服务端；客户端提交的任何订单号字段一律 400（见 `03-商品与支付接口预留.md` 的禁用字段表） |

为什么前缀留 `CB`：这是"在线书店（Course Bookstore）"的固定前缀，对账文件里一眼能看出业务线；
将来若扩多业务线，前缀是唯一需要变的部分，长度不变，`CHAR(20)` 不受影响。

为什么日期放在编号里：运营与客服按日期检索时不必查库；代价是"下单量"这一信息可按天被观察到——
这是可接受的，因为日订单量本身不是秘密，而**单笔订单的可枚举性**才是要防的。

## 4. DDL 草案（只作契约，本期不执行）

**MySQL 5.7**

```sql
CREATE TABLE order_header (
    order_id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    order_no          CHAR(20) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
    user_id           BIGINT UNSIGNED NOT NULL,
    status            ENUM('pending_payment','paid','shipped','completed','cancelled','refunded')
                      NOT NULL DEFAULT 'pending_payment',
    amount_total      DECIMAL(12,2) NOT NULL,
    currency          CHAR(3) NOT NULL DEFAULT 'CNY',
    idempotency_key   CHAR(36) CHARACTER SET ascii COLLATE ascii_bin NULL,
    created_at        DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    paid_at           DATETIME(3) NULL,
    updated_at        DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
                      ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (order_id),
    UNIQUE KEY uq_order_no (order_no),
    UNIQUE KEY uq_order_idempotency (user_id, idempotency_key),
    KEY idx_order_user_created (user_id, created_at),
    CONSTRAINT fk_order_user FOREIGN KEY (user_id)
        REFERENCES user_account (user_id) ON DELETE RESTRICT ON UPDATE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**SQLite（等价，供本地跑）**

```sql
CREATE TABLE order_header (
    order_id        INTEGER PRIMARY KEY AUTOINCREMENT,
    order_no        TEXT    NOT NULL UNIQUE,
    user_id         INTEGER NOT NULL REFERENCES user_account (user_id),
    status          TEXT    NOT NULL DEFAULT 'pending_payment',
    amount_total    TEXT    NOT NULL,          -- 定点两位小数字符串，不用浮点
    currency        TEXT    NOT NULL DEFAULT 'CNY',
    idempotency_key TEXT,
    created_at      TEXT    NOT NULL,
    paid_at         TEXT,
    updated_at      TEXT    NOT NULL
);
CREATE UNIQUE INDEX uq_order_idempotency ON order_header (user_id, idempotency_key);
```

两点与用户表保持一致的约定：金额用**定点两位小数字符串**（`"45.00"`），时间用 ISO-8601 UTC；
这两条与 `01` 的 §5 C-04 同源。

## 5. 冻结项与不变式（II 阶段逐条对照）

1. `order_id` 的名称与类型不得改；不得改成 UUID。
2. `order_no` 的长度不得缩短，前缀不得改；`CHAR(20)` 是定长，改长度等于改所有对账文件格式。
3. `order_no` **必须**由服务端生成，且必须来自 CSPRNG；不得用"日期 + 自增"拼接。
4. 订单的归属字段名固定为 `user_id`，类型与 `user_account.user_id` 完全一致。
5. 状态机取值固定为 §4 DDL 里的六个；新增状态走变更记录，且必须同时给出迁移规则。
6. 幂等键的维度是 `(user_id, idempotency_key)`，不是全局唯一——两个用户可以用同一个 UUID。
7. 除主键外**不允许**出现第二个"业务编号"（如 `trade_no`）；支付机构流水号是 `payment_record`
   的字段，不是订单的。

## 6. 生成函数签名（契约，不含实现）

```python
def new_order_no(now: datetime) -> str:
    """返回 20 字符订单编号：CB + YYYYMMDD + 10 位 Crockford Base32（CSPRNG）。

    不变式：
    - 长度恒为 20，字符集 [0-9A-HJKMNP-TV-Z]；
    - 同一用户连续两单之间无可推导关系；
    - 不读取 order_id，不依赖数据库自增。
    """
```

本期**不实现**这个函数（下单属项目 II）。此处只固定签名与不变式，保证 II 阶段写出来的
编号能直接进入对账文件，不需要回头改格式。

| 写对账文件 | 用 `order_no` 作唯一列，长度 20，可定长解析 |
