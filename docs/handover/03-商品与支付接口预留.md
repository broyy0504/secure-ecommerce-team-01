| 项目 | 内容 |
| :--- | :--- |
| 文档编号 | HO-03 |
| 状态 | **冻结（V1.0）**：签名与返回结构定稿；实现留给项目 II |
| 依据 | 任务书 2.5"只写契约、不写实现：路由可以先存在，但要明确返回未实现，不能返回假数据" |
| 本期实现状态 | 下列 9 条路由**已存在**，全部返回 `501 NOT_IMPLEMENTED` + `traceId`，**不返回任何假数据** |

## 1. 通用约定（II 阶段沿用，不必重新讨论）

| 约定 | 内容 |
| :--- | :--- |
| 身份来源 | 只从 `Authorization: Bearer <token>` 解析；请求体/查询串里的 `userId`、`role`、`merchantId` 一律 400 |
| 错误结构 | `{code, message, traceId, details?}`，错误码取 `src/user/errors.py` 的封闭集，不临时拼字符串 |
| 金额 | **字符串**定点两位小数（如 `"45.00"`），币种固定 `CNY`；服务端计算，客户端提交金额一律 400 |
| 时间 | ISO-8601 UTC，毫秒 3 位 + `Z`（与用户表同口径） |
| 归属 | 越权访问返回 **404** 而非 403；响应体与"不存在"逐字一致（除 `traceId`） |
| 幂等 | 下单用客户端生成的 `idempotencyKey`（UUIDv4）；支付回调用 `channelTradeNo` |
| 未实现 | 返回 `501 {"code":"NOT_IMPLEMENTED","message":"该接口属项目 II 范围，本期未实现","traceId":"…"}`，**不返回空数组冒充"没有数据"** |

> 关于 `NOT_IMPLEMENTED`：它**不在** 14 条封闭错误码里，因为已实现的接口永远不会返回它。
> 它是"路由占位"的约定值，只用于本期这 9 条预留路由。II 阶段实现后，该码从这些路由上消失，
> 封闭集不受影响。

## 3. 逐条签名与返回

### 3.1 `GET /api/books`

```text
查询参数：page（整数 ≥1，默认 1）、size（整数 1—50，默认 20）、keyword（≤64 字符，可选）
响应 200：{ items: [{ bookId: "301", title: "…", author: "…", price: "45.00", currency: "CNY",
                     stockState: "in_stock" | "out_of_stock" }],
            page: 1, size: 20, total: 137 }
错误：400 VALIDATION_ERROR / 429 RATE_LIMITED / 500 INTERNAL_ERROR
```

`stockState` 只给"有没有货"，**不给精确库存数**（精确数会被用来推算销量，也会给抢购脚本当信号）。

### 3.2 `GET /api/books/{bookId}`

```text
路径参数：bookId（1—19 位数字）
响应 200：{ bookId, title, author, publisher, isbn, price, currency, description, coverUrl, stockState }
错误：400 VALIDATION_ERROR / 404 RESOURCE_NOT_FOUND（下架与不存在同形）/ 500 INTERNAL_ERROR
```

### 3.3 `GET /api/cart`

```text
响应 200：{ items: [{ bookId, title, price, currency, quantity, amountLine }], amountTotal, currency }
错误：401 AUTH_UNAUTHENTICATED / 401 AUTH_TOKEN_EXPIRED / 500 INTERNAL_ERROR
```

### 3.4 `POST /api/cart/items`

```text
请求体（additionalProperties: false）：
  { bookId: "301", quantity: 1 }        quantity 整数 1—99
响应 200：{ items: [...], amountTotal, currency }   ← 返回整车，减少前端合并逻辑
错误：400 VALIDATION_ERROR / 401 / 404 RESOURCE_NOT_FOUND（图书下架）/ 409 ORDER_STOCK_INSUFFICIENT / 500
禁用字段：userId、unitPrice、amountLine、amountTotal、currency
```

### 3.5 `DELETE /api/cart/items/{bookId}`

```text
响应 204（幂等：删不存在的条目也返回 204，不确认"这条曾经存在"）
错误：400 VALIDATION_ERROR / 401 / 500
```

### 3.6 `POST /api/orders`

```text
请求体（additionalProperties: false）：
  { idempotencyKey: "<UUIDv4>",
    addressId: "10001",
    items: [{ bookId: "301", quantity: 1 }],   // 1—20 项，bookId 不得重复
    remark: "…" }                              // 可选，≤200 字符
响应 201：{ orderId: "CB20261110K7F3Q9M2XT",   // 值来自 order_no，见 02 号文件
            status: "pending_payment",
            amountTotal: "45.00", currency: "CNY",
            expiresAt: "2026-11-10T03:00:00.000Z",
            items: [{ bookId, title, unitPrice, quantity, amountLine }] }
错误：400 VALIDATION_ERROR（含禁用字段、条目超限、数量越界）
      401 AUTH_UNAUTHENTICATED / 403 AUTH_FORBIDDEN（非买家）
      404 RESOURCE_NOT_FOUND（图书下架或地址不属于本人，同形）
      409 ORDER_STOCK_INSUFFICIENT / 409 IDEMPOTENCY_CONFLICT
      413 PAYLOAD_TOO_LARGE / 429 RATE_LIMITED / 500
禁用字段：orderId、orderNo、userId、merchantId、unitPrice、totalAmount、amount、status、paidAt、currency
```

事务与并发：订单头、明细、价格快照、库存占用在同一事务内提交；库存扣减用原子条件更新
（`UPDATE … SET available = available - ? WHERE available >= ?`），失败即 409，不重试到超卖。

### 3.7 `GET /api/orders/{orderId}`

```text
路径参数：orderId（对外编号，20 字符，正则 ^CB[0-9]{8}[0-9A-HJKMNP-TV-Z]{10}$）
响应 200：{ orderId, status, amountTotal, currency, createdAt, paidAt, items: [...], address: {...} }
错误：400 VALIDATION_ERROR（格式不符，不落到查询）
      401 AUTH_UNAUTHENTICATED / 404 RESOURCE_NOT_FOUND（他人订单与不存在同形）/ 500
```

### 3.8 `POST /api/payments/callback`

```text
请求体（JSON，≤8 KB；**先验签再反序列化**）：
  { channelTradeNo: "…",      ≤64
    orderNo: "CB…",           ≤32
    amount: "45.00",         定点两位小数字符串
    currency: "CNY",
    status: "SUCCESS" | "FAILED" | "REFUNDED",
    paidAt: "2026-11-10T02:00:00.000Z",
    nonce: "…",               ≤64
    timestamp: 1793746800,    Unix 秒
    signature: "…" }          ≤128
响应 200：{ code: "SUCCESS" }        （重复回调同样返回 SUCCESS，但不再改任何状态）
错误：401 PAY_SIGNATURE_INVALID（签名错、时间戳越窗 ±300 秒、nonce 重放）
      400 VALIDATION_ERROR / 404 RESOURCE_NOT_FOUND（订单号不存在）
      409 PAY_AMOUNT_MISMATCH / 429 RATE_LIMITED / 500
鉴权：不用用户令牌；四重校验 = 报文签名 → 时间窗 → nonce 未重复 → 来源白名单；不开放跨域
```

### 3.9 `POST /api/auth/cert/verify`

```text
证书认证是 II 阶段扩展（任务书原文"为项目 II 扩展证书认证…预留接口"）。

请求体：{ certChain: [...], challenge: "<服务端下发的一次性随机串>" }
响应 200：{ subject: "<CN>", userId: "1", expiresAt: "…" }
错误：400 VALIDATION_ERROR / 401 AUTH_UNAUTHENTICATED（证书链无效、挑战值过期）/ 500
约定：挑战值一次性，5 分钟内有效；证书主体与 username 的绑定关系存在独立表中，
      **不往 user_account 加证书列**（见 §4）。
```

## 4. 不许把 II 的字段提前塞进用户表

任务书原话："商品、购物车、下单、支付、证书认证这五块一律不实现，字段也不要提前塞进用户表。"

| 字段 | 会出现在哪 | 为什么不能进 `user_account` |
| :--- | :--- | :--- |
| `merchant_id` | 商品、订单 | 商户是另一种身份，II 阶段用 `user_role_relation` 表达，不是"用户表多一列" |
| `price`、`amount`、`currency` | 订单、商品 | 金额属于订单，用户没有金额 |
| `address`、`addressId` | 订单 | 收货地址是独立表（一用户多地址），塞进用户表只能存一条 |
| `cart_json` | 购物车 | 购物车是独立表，塞 JSON 列会导致并发覆盖 |
| `cert_serial`、`cert_pem` | 证书认证 | 证书是独立表（一用户多证书、有有效期与吊销状态） |

这五类数据一旦进了用户表，II 阶段就只能"在用户表里加一堆可空列"，而 §3 的冻结规则不允许
随便改表。所以现在就不放。

## 5. 本期这 9 条路由实际返回什么

```http
POST /api/orders HTTP/1.1
Authorization: Bearer <任意>
Content-Type: application/json

HTTP/1.1 501 Not Implemented
Content-Type: application/json; charset=utf-8
Cache-Control: no-store

{"code":"NOT_IMPLEMENTED","message":"该接口属项目 II 范围，本期未实现","traceId":"be6a33ca3dcc0305"}
```

三条纪律：

1. **不返回空数组**。空数组会让调用方以为"功能好了，只是没数据"，掩盖未实现的事实。
2. **不返回假数据**。不编造 `orderId`、不返回示例金额。
3. **不写库**。这 9 条路由不进数据库、不产生任何记录。
