# 在线书店系统角色权限清单

本清单依据本组 README 确定的在线书店电商场景与项目 I 功能范围编制，用于统一用户模块、商品模块和交易模块的身份鉴权与访问控制设计。系统采用前后端分离架构，认证、鉴权、数据访问和敏感操作必须由后端 API 校验；前端隐藏入口不能替代权限控制。

## 一、适用范围与原则

- 业务场景：纸质书零售，主要服务普通读者、学生及藏书爱好者。
- 核心功能：注册登录、密码加密传输、个人中心；商品详情、商品管理；购物车、订单支付、支付信息加密、订单处理。
- 权限原则：默认拒绝、最小权限、职责分离、数据最小化、关键操作可审计。
- 未登录访客不是独立业务角色，只具有浏览、搜索和查看公开书籍详情的匿名访问状态；下单、支付、评价、售后和个人中心等操作必须登录。

## 二、角色定义与权限边界

| 角色 | 类型 | 主要职责 | 允许执行的操作 | 数据访问范围 | 禁止或限制执行的操作 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 买家 | 内部业务角色 | 浏览、购买书籍并管理本人交易 | 注册、登录、修改本人密码；浏览和搜索书籍；管理本人购物车、收货地址；创建及取消未支付订单；发起支付；查看本人订单和物流；确认收货；评价已完成订单；发起退货或售后申请 | 本人账户资料、购物车、收货地址、订单、支付状态、评价和售后记录 | 不得管理书籍、库存和价格；不得访问其他用户资料或订单；不得修改订单金额、支付结果和物流状态；不得获取支付凭证或明文密码 |
| 商户 | 内部业务角色 | 管理本店书籍并完成订单履约 | 经审核后登录商户端；维护本店书籍信息（ISBN、书名、作者、出版社、封面、简介、价格、库存）；上架、下架或软删除本店书籍；处理本店订单并发货；响应本店售后；查看本店库存和经营统计 | 本店书籍、库存、订单、售后和经营统计；仅限订单履约所必需的收货信息 | 不得管理其他商户的书籍和订单；不得直接修改订单金额或支付状态；不得查看与履约无关的买家资料；不得查看或保存支付敏感信息；不得绕过平台流程处理退款 |
| 管理员 | 内部业务角色 | 维护平台秩序并执行安全审计 | 审核商户资质和商品内容；管理分类、违规内容和账号封禁；按流程处理订单争议及退款；配置授权范围内的角色权限；查询安全与审计日志；执行必要的风险控制 | 授权范围内的平台业务数据、脱敏用户信息和操作日志；支付数据仅可访问处理业务所必需的脱敏结果 | 不得查看明文密码或完整支付凭证；不得无授权查询、导出用户数据；不得绕过审批直接修改订单和支付结果；不得删除或篡改审计日志；不得利用权限为自己或关联商户谋利 |
| 支付机构 | 外部系统 | 处理支付并返回可信结果 | 接收经过签名的支付或退款请求；返回处理结果；通过约定接口回调支付状态；按接口查询必要交易结果 | 支付订单号、金额、币种、支付状态、商户号及完成交易所必需的技术信息 | 不得直接访问业务数据库；不得在无有效请求时发起支付或退款；不得修改书籍、订单或库存；不得保存与支付无关的用户数据；不得向未授权系统暴露接口凭证 |

## 四、数据与敏感信息规则

1. **账号密码**：密码必须通过 HTTPS/TLS 传输，后端使用加盐不可逆哈希保存；日志、异常信息和接口响应中不得出现明文密码或可逆密文。
2. **支付信息**：支付信息必须加密传输；系统不得存储银行卡验证码等非必要敏感数据。支付回调必须验签、校验金额和订单号，并使用幂等机制防止重复入账。
3. **个人信息**：买家资料、地址和订单信息只能在完成交易所必需的范围内使用；商户只能查看履约所需的收货信息；管理员查看敏感字段时应脱敏。
4. **对象级隔离**：后端必须同时校验“角色权限”和“资源归属”。买家资源以本人 `user_id` 为边界，商户资源以本店 `merchant_id` 为边界，禁止仅凭前端传入的编号访问他人数据。
5. **多角色账号**：一个账号原则上绑定一个主业务角色；如确需多角色，必须显式授权并在每次操作时按当前业务身份重新鉴权，不能默认继承最高权限。
6. **状态可信**：订单状态、支付状态、库存扣减和退款结果只能由后端服务按业务流程变更，客户端不得直接指定或覆盖。

## 五、鉴权与审计要求

- 登录成功后由后端建立会话或签发访问凭证，并设置有效期、失效和重新认证机制。
- 修改角色、审核商户、封禁账号、退款、导出数据等高风险操作应进行二次确认或重新认证，并记录原因。
- 审计日志至少包含操作人、操作时间、操作对象、操作类型、请求来源、执行结果和必要追踪编号，且不得记录密码、支付凭证等敏感信息。
- 账号被停用、权限被撤销或商户被关停后，应立即回收会话、令牌和相关接口凭证。
- 所有未授权访问和越权尝试应被后端拒绝，并按安全策略记录；不因前端未展示入口而默认安全。
- 支付机构使用专有接口凭证和最小接口范围，凭证应支持轮换、撤销与异常调用监控。

## 六、授权与变更规则

- 买家通过自主注册获得权限。
- 商户通过申请并经管理员审核后获得商户权限，未审核或审核不通过的账号不得管理书籍和订单。
- 管理员权限由授权人员分配，遵循最小权限和职责分离原则，并定期复核。
- 支付机构通过经批准的接口凭证接入，仅开通支付、退款和状态查询所必需的接口。
- 任何角色变更都应记录操作人、时间、变更前后权限和审批依据。

## 七、权限验收要点

- 买家无法进入商品管理功能，也不能通过直接调用 API 修改书籍、库存、价格或支付结果。
- 商户只能操作本店书籍和订单，无法读取或修改其他商户的数据。
- 管理员不能查看明文密码或完整支付凭证，不能绕过流程修改交易记录。
- 支付机构不能直接访问业务数据库，伪造或未验签的回调必须被拒绝。
- 用户、商户和订单接口均需验证登录身份及资源归属，越权请求应返回拒绝结果并写入审计日志。
