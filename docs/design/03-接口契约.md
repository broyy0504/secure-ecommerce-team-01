## 1. 契约总则

1. **四要素齐全才算契约**：每个接口必须写清输入约束、输出、错误码、鉴权。缺任一项，该接口视为未定义。
2. **身份只有一个来源**：受保护接口的调用者身份只从 `Authorization: Bearer <token>` 解析。请求体、查询串、路径中的用户标识与角色一律不作为授权依据。
3. **默认拒绝**：未在本文列出的字段、角色、状态迁移，一律拒绝。请求体 schema 全部 `additionalProperties: false`。
4. **错误码是封闭集合**：对外只允许出现 §2 表中的错误码。新增错误码须同步改本文，不得临时拼字符串。
5. **错误文案不解释内部状态**：`message` 只说明"能不能做"，不说明"为什么不能"到能推断表结构、字段名、账号存在性或锁定状态的粒度。
6. **金额用字符串**：定点两位小数字符串，币种固定 `CNY`，服务端计算，客户端提交的金额类字段一律拒绝。
7. **写操作带追踪**：所有错误响应与所有写操作审计都带同一个 `traceId`，用于把用户看到的现象与服务端记录对上。

## 2. 错误码封闭集

对外只允许出现以下 14 个错误码。表中"对外文案"即响应 `message` 的原文，不得按场景改写。

| 错误码 | HTTP | 对外文案 | 触发条件 | 允许出现在 |
| :--- | :--- | :--- | :--- | :--- |
| `VALIDATION_ERROR` | 400 | 请求参数不合法 | 字段缺失、类型错、超长、格式不符、出现禁用字段 | 全部接口 |
| `PAYLOAD_TOO_LARGE` | 413 | 请求体过大 | 超过该接口声明的体积上限 | 全部接口 |
| `AUTH_INVALID_CREDENTIALS` | 401 | 账号或密码错误 | 账号不存在、口令错误、账号被锁定、账号被停用（四种情况同一文案） | 登录 |
| `AUTH_UNAUTHENTICATED` | 401 | 登录状态无效，请重新登录 | 令牌缺失、格式非法、被篡改、已被撤销 | 全部受保护接口 |
| `AUTH_TOKEN_EXPIRED` | 401 | 登录已过期，请重新登录 | 令牌签名有效但已过期 | 全部受保护接口 |
| `AUTH_FORBIDDEN` | 403 | 无权执行该操作 | 角色不允许、越权访问管理端 | 受保护接口 |
| `RESOURCE_NOT_FOUND` | 404 | 资源不存在 | 资源不存在、已下架、不属于当前用户（三者同一响应） | 订单、地址、图书 |
| `USER_ALREADY_EXISTS` | 409 | 该登录名或手机号已被使用 | 登录名或手机号唯一约束冲突 | 注册 |
| `ORDER_STOCK_INSUFFICIENT` | 409 | 所选图书库存不足 | 扣减时可售量不足 | 下单 |
| `IDEMPOTENCY_CONFLICT` | 409 | 重复提交内容不一致 | 同一幂等键对应不同请求体 | 下单 |
| `PAY_AMOUNT_MISMATCH` | 409 | 支付金额与订单不一致 | 回调金额与订单应付金额不等 | 支付回调 |
| `PAY_SIGNATURE_INVALID` | 401 | 支付回调验签失败 | 签名错误、时间戳超出窗口、随机串重放 | 支付回调 |
| `RATE_LIMITED` | 429 | 请求过于频繁，请稍后再试 | 超过该接口的频率阈值 | 全部接口 |
| `INTERNAL_ERROR` | 500 | 服务暂时不可用，请稍后再试 | 未预期异常 | 全部接口 |

**统一错误响应结构**

```json
{
  "code": "VALIDATION_ERROR",
  "message": "请求参数不合法",
  "traceId": "0f3c1b7e9a2d4c56",
  "details": [
    { "field": "password", "reason": "TOO_LONG" }
  ]
}
```

`details` 的约束：

1. `field` 只允许出现**请求字段名**，且必须在各接口声明的字段白名单内。不得出现数据库列名、表名、嵌套路径以外的内部标识。
2. `reason` 只允许枚举：`REQUIRED`、`TYPE_MISMATCH`、`TOO_SHORT`、`TOO_LONG`、`FORMAT_INVALID`、`OUT_OF_RANGE`、`NOT_ALLOWED`、`DUPLICATE`。
3. 不得回显用户提交的原值——把攻击者构造的串原样送进日志与页面，等于帮他传播。
4. `details` 可省略；`code`、`message`、`traceId` 三者必须出现。

## 4. 核心接口契约

### 4.1 API-USER-001 注册

`POST /api/users/register`

| 要素 | 内容 |
| :--- | :--- |
| **输入约束** | ① 传输：`Content-Type: application/json; charset=utf-8`，请求体 ≤ 4 KB。<br/>② 字段：`username` 必填，字符串，去首尾空白后 4—32 字符，匹配 `^[A-Za-z0-9_]{4,32}$`；`phone` 必填，字符串，去空格与连字符后匹配 `^1[3-9]\d{9}$`；`password` 必填，字符串，8—64 个字符且 UTF-8 字节数 ≤ 256，不得全为同一字符，不得等于 `username` 或 `phone`。<br/>③ 禁用字段：`userId`、`role`、`status`、`iterations`、`salt`、`passwordHash`、`passwordDerived`。出现任一即 `400 VALIDATION_ERROR`，不静默忽略。<br/>④ 未知字段：`additionalProperties: false`，一律 `400`。 |
| **输出** | 成功 `201`，响应体：`{ "userId": "10001", "username": "reader_01", "phoneMasked": "138****8000", "status": "active", "createdAt": "2026-10-20T01:02:03.456Z" }`。<br/>响应头：`Cache-Control: no-store`、`Content-Type: application/json; charset=utf-8`。<br/>**不返回**：口令、派生值、盐、迭代次数、手机号明文、任何内部列名。 |
| **错误码** | `VALIDATION_ERROR`(400)、`USER_ALREADY_EXISTS`(409)、`PAYLOAD_TOO_LARGE`(413)、`RATE_LIMITED`(429)、`INTERNAL_ERROR`(500)。<br/>`409` 的 `message` 固定为"该登录名或手机号已被使用"，**不得**指出是哪一个冲突，也不得返回该手机号的任何其他信息。 |
| **鉴权** | 公开接口，不需要令牌。<br/>限流：单 IP 每小时 10 次、单设备指纹每小时 5 次；同一手机号 60 秒内只接受一次提交。<br/>限流命中返回 `429`，不得因限流把已存在账号的 `409` 改成别的语义。 |
| 幂等 | 无幂等键。重复提交由限流与唯一约束共同收敛。 |
| 审计 | 记录结果、`traceId`、脱敏账号；不记口令、派生值、盐。 |

**关于账号枚举的取舍**：注册接口的 `409` 必然暴露"此手机号已注册"。这一点无法靠改文案消除（否则用户无法知道该换手机号还是该去登录）。因此本契约**不假装它不存在**，而是用限流把探测速率压到每小时个位数，并在 SR-20 里给出可验证的判定方法。

### 4.2 API-AUTH-001 登录

`POST /api/auth/login`

| 要素 | 内容 |
| :--- | :--- |
| **输入约束** | ① 传输：JSON，请求体 ≤ 2 KB。<br/>② 字段：`account` 必填，字符串 4—64 字符，允许登录名格式或手机号格式，服务端归一化（去首尾空白、手机号去分隔符）后再查；`password` 必填，8—64 字符，不做格式拒绝以外的强度判断（强度在注册时把关，登录时只验证）。<br/>③ 禁用字段：`role`、`userId`、`iterations`、`salt`、`rememberMe`（本期不支持长效令牌）。<br/>④ 未知字段：一律 `400`。 |
| **输出** | 成功 `200`，响应体：`{ "accessToken": "<32 字节随机值的编码>", "tokenType": "Bearer", "expiresIn": 7200, "user": { "userId": "10001", "username": "reader_01", "role": "buyer" } }`。<br/>响应头：`Cache-Control: no-store`。<br/>令牌只在这一次响应中出现，之后只能由客户端回传，服务端不再重复下发。 |
| **错误码** | `VALIDATION_ERROR`(400)、`AUTH_INVALID_CREDENTIALS`(401)、`RATE_LIMITED`(429)、`INTERNAL_ERROR`(500)。<br/>**账号不存在、口令错误、账号被锁定、账号被停用四种情况，一律返回 `401 AUTH_INVALID_CREDENTIALS`**，`message` 逐字相同，不得附加任何区分性提示。 |
| **鉴权** | 公开接口，不需要令牌。<br/>限流：单账号 10 次 / 15 分钟（失败后触发、成功后清零）、单 IP 30 次 / 15 分钟；命中后指数退避。锁定阈值最终取值见 C-04（`SR-AUTH-002` 为 5 次、`FR-USER-007` 为 10 次，两处待统一），**无论取哪一个，本接口的对外文案与状态码都不随之改变**。<br/>账号不存在时仍执行一次同参数的口令派生，保证与"账号存在但口令错"耗时同量级。 |
| 幂等 | 每次成功登录签发新令牌，不复用旧令牌；旧令牌不受影响（多设备并存）。 |
| 审计 | `login_log` 记录 `result`、`failure_code`、`trace_id`、来源地址、脱敏账号；不记口令、令牌。 |

**与第 4 周草案的差异**：草案用 `423 AUTH_ACCOUNT_LOCKED` 表示锁定。`423` 等于告诉调用方"这个账号存在且被锁了"，与本表"四种情况同一响应"的目标直接冲突。本契约统一为 `401`，锁定事实只进内部审计。差异登记为 C-01，见 [`04-控制指认与整改输入.md`](./04-控制指认与整改输入.md) §4。

### 4.3 API-AUTH-002 退出

`POST /api/auth/logout`

| 要素 | 内容 |
| :--- | :--- |
| **输入约束** | ① 无请求体；允许传空对象 `{}`，也允许完全不传 body。<br/>② 不接受 `userId`、`sessionId`、`token` 等参数——要撤销哪个会话，由请求头里的令牌本身决定。<br/>③ 若传 body 且含字段，一律 `400`。 |
| **输出** | 成功 `204 No Content`，无响应体。<br/>已撤销的令牌再次调用，仍返回 `204`（幂等），不返回 `401`——返回 `401` 会额外确认"该令牌曾经有效"。 |
| **错误码** | `AUTH_UNAUTHENTICATED`(401)（令牌缺失或格式非法）、`VALIDATION_ERROR`(400)（附带了字段）、`INTERNAL_ERROR`(500)。 |
| **鉴权** | 必须携带有效令牌。<br/>只能撤销**当前请求所用令牌对应的那一个会话**，不得撤销该用户的其他会话（其他设备保持登录）。<br/>管理员撤销他人会话走独立的管理端接口，不在本接口范围。 |
| 幂等 | 是。重复调用结果一致。 |
| 审计 | 记录 `revoked_at`、`revoke_reason = 'logout'`、`trace_id`；不记令牌内容。 |

### 4.4 API-USER-002 查询本人信息

`GET /api/users/me`

| 要素 | 内容 |
| :--- | :--- |
| **输入约束** | ① 不接受任何请求参数。出现 `userId`、`id` 一类查询参数时**忽略并记审计**——该接口的语义就是"令牌对应的人"，多传参数本身就是探测行为。<br/>② 不接受请求体。 |
| **输出** | `200`，响应体：`{ "userId", "username", "nickname", "phoneMasked", "emailMasked", "status", "lastLoginAt", "createdAt" }`。<br/>手机号、邮箱固定脱敏；`status` 只返回本人可见的取值。 |
| **错误码** | `AUTH_UNAUTHENTICATED`(401)、`AUTH_TOKEN_EXPIRED`(401)、`INTERNAL_ERROR`(500)。 |
| **鉴权** | Bearer 令牌；身份只从令牌解析。角色不限（买家、商户、管理员均可查自己）。<br/>不校验角色，但必须校验"查的是自己"——这一点由接口不接收用户标识来保证，而不是靠比对参数。 |
| 审计 | 查询行为可按策略记录；不记返回内容。 |

### 4.5 API-ORDER-001 下单

`POST /api/orders`

> 本接口在 `API草案V1` §5 中被列为 P2 预留。第 6-9 周要求设计下单流程，因此本节给出完整安全契约与字段需求；**实现仍归后续阶段**，`db/` 与业务代码不在本阶段范围。

| 要素 | 内容 |
| :--- | :--- |
| **输入约束** | ① 传输：JSON，请求体 ≤ 8 KB。<br/>② `idempotencyKey` 必填，字符串，UUIDv4 格式 `^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$`，由客户端生成、同一次下单重试时复用。<br/>③ `addressId` 必填，数字字符串 1—19 位，必须属于当前用户。<br/>④ `items` 必填，数组 1—20 项，每项为 `{ "bookId": 数字字符串 1—19 位, "quantity": 整数 1—99 }`；`bookId` 不得重复。<br/>⑤ `remark` 可选，字符串 ≤ 200 字符，需过滤控制字符与换行；`couponCode` 可选，匹配 `^[A-Z0-9]{4,32}$`。<br/>⑥ **禁用字段**：`userId`、`role`、`merchantId`、`unitPrice`、`totalAmount`、`amount`、`status`、`paidAt`、`orderNo`、`currency`。出现任一即 `400` 并记审计——金额、归属、状态、订单号全部由服务端生成，客户端没有任何理由提交它们。<br/>⑦ 未知字段：一律 `400`。 |
| **输出** | 成功 `201`，响应体：`{ "orderId": "20001", "orderNo": "CB20261020A7F3K9", "status": "pending_payment", "amountTotal": "45.00", "currency": "CNY", "expiresAt": "2026-10-20T01:32:03.456Z", "items": [ { "bookId": "301", "title": "<书名快照>", "unitPrice": "45.00", "quantity": 1, "amountLine": "45.00" } ] }`。<br/>`orderNo` 为不可预测的对外编号，不用自增主键。<br/>同样 `idempotencyKey` 重复提交，返回同一 `orderId` 与同一 `orderNo`。 |
| **错误码** | `VALIDATION_ERROR`(400)（含禁用字段、条目超限、数量越界）、`AUTH_UNAUTHENTICATED`(401)、`AUTH_FORBIDDEN`(403)（非买家角色）、`RESOURCE_NOT_FOUND`(404)（图书不存在/已下架、地址不属于本人，两者同一响应）、`ORDER_STOCK_INSUFFICIENT`(409)、`IDEMPOTENCY_CONFLICT`(409)、`PAYLOAD_TOO_LARGE`(413)、`RATE_LIMITED`(429)、`INTERNAL_ERROR`(500)。<br/>`404` 不得区分"图书下架"与"地址不属于你"；`409` 库存不足时不得返回精确库存数或他人订单信息。 |
| **鉴权** | Bearer 令牌 + 角色为买家。<br/>三元校验：令牌有效 → 角色允许 → **`addressId` 归属当前用户**；三者任一不过即拒绝。<br/>限流：单用户 20 次 / 分钟；同一幂等键不重复计费。 |
| 幂等 | 必填 `idempotencyKey`；同键同体返回首次结果，同键不同体返回 `409 IDEMPOTENCY_CONFLICT`。 |
| 事务 | 订单头、订单明细、价格快照、库存占用在同一事务内提交；库存扣减用原子条件更新，冲突重试有上限。 |
| 审计 | 记录建单结果、`traceId`、订单号、被拒绝的禁用字段名；不记完整收货信息。 |

### 4.6 API-ORDER-002 查询订单

`GET /api/orders/{orderId}`

| 要素 | 内容 |
| :--- | :--- |
| **输入约束** | ① 路径参数 `orderId` 必填，数字字符串 1—19 位，格式不符直接 `400`（不落到查询）。<br/>② 不接受 `userId` 等归属参数；归属只从令牌取。<br/>③ 不接受请求体。 |
| **输出** | `200`，响应体：订单头（`orderId`、`orderNo`、`status`、`amountTotal`、`currency`、`createdAt`、`paidAt`）+ 明细数组 + 收货信息（买家看自己完整信息，商户只看履约所需，管理员看脱敏）。<br/>不同角色返回字段不同，按最小必要裁剪。 |
| **错误码** | `VALIDATION_ERROR`(400)、`AUTH_UNAUTHENTICATED`(401)、`RESOURCE_NOT_FOUND`(404)、`INTERNAL_ERROR`(500)。<br/>**访问他人订单返回 `404`，不返回 `403`**，且响应体与"订单不存在"逐字一致。 |
| **鉴权** | Bearer 令牌。<br/>买家：`order.user_id` 必须等于令牌用户；商户：`order.merchant_id` 必须属于本店；管理员：按授权范围。<br/>三元校验缺一不可；越权尝试必须记审计（操作人、目标订单、结果）。 |
| 审计 | 越权尝试必记；正常查询按策略记。 |

### 4.7 API-PAY-001 支付回调

`POST /api/payments/callback`

> 属外部集成边界（`API草案V1` §5 已保留路径）。本期不接真实支付，但契约按可实现的验签模型写死，避免将来"先跑通再补安全"。

| 要素 | 内容 |
| :--- | :--- |
| **输入约束** | ① 传输：JSON，请求体 ≤ 8 KB；**签名针对原始字节计算，必须先验签再反序列化**——先解析再拼串验签会被字段顺序、额外字段、编码差异绕过。<br/>② 字段：`channelTradeNo` 必填 ≤ 64、`orderNo` 必填 ≤ 32、`amount` 必填定点两位小数字符串、`currency` 必填固定 `CNY`、`status` 必填 ∈ {`SUCCESS`,`FAILED`,`REFUNDED`}、`paidAt` 必填 ISO 8601 UTC、`nonce` 必填 ≤ 64、`timestamp` 必填 Unix 秒、`signature` 必填 ≤ 128。<br/>③ 时间戳与服务器时间偏差 > 300 秒即拒绝；`nonce` 在 5 分钟窗口内不得重复。<br/>④ 未知字段：不参与验签，且不影响验签结果判定（以原始字节为准）。 |
| **输出** | 成功 `200`，响应体 `{ "code": "SUCCESS" }`（按机构约定格式）。<br/>重复回调同样返回 `SUCCESS`，但不再改动任何状态。 |
| **错误码** | `PAY_SIGNATURE_INVALID`(401)（签名错、时间戳越窗、随机串重放）、`VALIDATION_ERROR`(400)、`RESOURCE_NOT_FOUND`(404)（订单号不存在）、`PAY_AMOUNT_MISMATCH`(409)、`RATE_LIMITED`(429)、`INTERNAL_ERROR`(500)。<br/>验签失败时**不得**回传"签名错误在哪一位"、密钥标识、期望签名值等任何可用于构造正确签名的信息。 |
| **鉴权** | 不使用用户令牌。<br/>四重校验：报文签名 → 时间戳窗口 → 随机串未重复 → 来源地址白名单。<br/>该路径**不开放跨域**，不接受浏览器会话凭据；凭据只从服务端密钥管理读取，不写入仓库与数据库。 |
| 幂等 | `channelTradeNo` 唯一索引；已成功入账的流水再次回调只返回成功，不重复改单、不重复记账。 |
| 审计 | 记录验签结果、来源、订单号、金额比对结果、`traceId`；不记密钥、完整报文原文。 |
